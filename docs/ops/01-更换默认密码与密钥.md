# 运维：更换线上默认密码与密钥

> 更新时间：2026-07-14
> 适用环境：阿里云轻量服务器 `106.15.89.180`，Docker Compose 部署（`deploy/docker-compose.yml`）
> 关联文档：`docs/09-部署上线指南.md`、根目录 `handoff.md`（待办 #1）

---

## 一、目标

把三处仍在用的默认凭据换成强密码：

| 凭据 | 默认值（待替换） | 环境变量 |
|------|----------------|---------|
| MySQL 业务账号密码 | `rbac_123` | `MYSQL_PASSWORD` |
| MySQL root 密码 | `rbac_root_123` | `MYSQL_ROOT_PASSWORD` |
| Redis 密码 | `rbac_redis_123` | `REDIS_PASSWORD` |
| JWT 签名密钥 | `rbac-server-default-secret-key-...` | `RBAC_JWT_SECRET` |

---

## 二、原理：三把密码的机制不同（关键）

后端读取方式决定了「改了能不能立即生效」：

| 密码 | 后端/容器怎么读 | 改 `.env` + 重启能否生效 | 备注 |
|------|----------------|------------------------|------|
| **Redis** `REDIS_PASSWORD` | 容器启动命令 `--requirepass`，每次启动都重读 | ✅ 立即生效 | 无坑 |
| **JWT** `RBAC_JWT_SECRET` | 后端进程启动时读环境变量 | ✅ 重建 backend 生效 | 改完**所有旧 Token 失效，用户需重新登录**（安全上正是要的效果） |
| **MySQL** `MYSQL_PASSWORD` | **仅在数据卷首次初始化**时写入账号 | ❌ 光改 `.env` 无效 | 见下方「MySQL 坑」 |

### MySQL 坑（务必理解）

`mysql-data` 数据卷在第一次 `docker compose up` 时，就已经把 `rbac / rbac_123` 账号密码烧进去了。之后 MySQL **不再读** `MYSQL_PASSWORD` 环境变量。
如果只改 `.env` 就重启，会变成「backend 用新密码连、MySQL 还认旧密码」→ **连不上**。

因此 MySQL 改密码要二选一：
- **方案 A（清库重建）**：删数据卷，MySQL 重新初始化时用新密码建账号。会丢运行期数据（回到种子状态）。
- **方案 B（保数据）**：进容器 `ALTER USER` 手动改，再让 `.env` 与之一致。

### 补充

- 本地 `deploy/.env` 已被 `.gitignore`，**不会推到服务器**。所以服务器原本没有 `.env`，用的是 compose 里的 `:-默认值` 兜底。**改密码 = 在服务器上新建一个 `.env`**。

## 三、生成强密码

在任意机器执行（`.env` 只放服务器，不要入库）：

```bash
echo "MYSQL_ROOT_PASSWORD=$(openssl rand -base64 18 | tr -d '/+=' | cut -c1-20)"
echo "MYSQL_PASSWORD=$(openssl rand -base64 18 | tr -d '/+=' | cut -c1-20)"
echo "REDIS_PASSWORD=$(openssl rand -base64 18 | tr -d '/+=' | cut -c1-20)"
echo "RBAC_JWT_SECRET=$(openssl rand -base64 48 | tr -d '/+=' | cut -c1-64)"
```

生成后用密码管理器存一份；丢了只能再走清库/改密流程。

---

## 四、方案 A（推荐）：清库重建

适用于刚上线的 MVP（库里只有种子数据，init SQL 会自动重灌）。

```bash
# 1) 上服务器进 deploy 目录
ssh root@106.15.89.180
cd /root/project/RBAC-Server/deploy

# 2) 新建 .env（把生成的强密码填进去）
cat > .env <<'EOF'
MYSQL_ROOT_PASSWORD=<强密码>
MYSQL_DATABASE=rbac
MYSQL_USER=rbac
MYSQL_PASSWORD=<强密码>
REDIS_PASSWORD=<强密码>
RBAC_JWT_SECRET=<强密钥>
EOF
chmod 600 .env

# 3) 停服务并删数据卷（-v 会清 MySQL/Redis 数据）
docker compose down -v

# 4) 重新起（环境变量变了，backend 要 --build 重建）
docker compose up -d --build

# 5) 验证
docker compose ps                       # 四个容器 Up / healthy
docker compose logs --tail=30 backend   # 无连不上 mysql/redis 报错
```

验证登录：浏览器开 `http://106.15.89.180`，用**初始 admin 账号**登录（清库后 admin 回到种子初始值）。

## 五、方案 B（备用）：保数据不删卷

库里已有不想丢的数据时用。**不要**执行 `down -v`。

```bash
cd /root/project/RBAC-Server/deploy

# 1) 用旧 root 密码进 mysql，手动改账号密码
docker compose exec mysql mysql -uroot -prbac_root_123 -e "
  ALTER USER 'rbac'@'%' IDENTIFIED BY '<新的 MYSQL_PASSWORD>';
  ALTER USER 'root'@'%' IDENTIFIED BY '<新的 MYSQL_ROOT_PASSWORD>';
  FLUSH PRIVILEGES;"

# 2) 建 .env（内容同方案 A 步骤 2，MySQL 密码必须与上面 ALTER 的完全一致）

# 3) 重建（不带 -v，数据保留）
docker compose up -d --build
```

> `.env` 里的 MySQL 密码与 `ALTER USER` 打的必须完全一致，否则 backend 连不上。

---

## 六、注意事项

- **JWT 换新后所有在线用户被登出**，需重新登录 —— 符合「旧 Token 必须失效」的安全红线。
- 服务器 `.env` 是敏感文件：`chmod 600`，**不 commit、不推 GitHub**。
- MySQL/Redis 端口虽在 compose 里映射到宿主机（3306/6379），但防火墙只放行 22/80，外网连不进来，这层是安全的。
