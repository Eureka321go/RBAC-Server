# IM 常用 Emoji 面板设计

## 目标

在现有聊天输入区增加应用内常用 Emoji 面板，使用户无需切换系统输入法即可快速选择表情。功能保持当前输入栏的紧凑布局，支持在光标位置插入、选区替换和安全退格，不改变文本消息协议。

本设计只覆盖聊天页的常用 Emoji 输入，不包含完整分类、搜索、肤色选择、最近使用记录、自定义表情或贴纸。

## 方案比较

### 方案 A：输入框内置入口与本地常用面板（采用）

在输入框右侧放置笑脸按钮。点击后收起系统键盘，并在输入区上方显示本地 Emoji 宫格。面板不依赖第三方库，表情作为普通 Unicode 文本写入现有草稿。

优点是入口直接、不新增外部按钮槽位、跨平台视觉一致；代价是需要维护一份有限的常用 Emoji 列表。

### 方案 B：输入框外增加独立按钮

实现简单且入口明显，但会再次压缩输入框宽度，与当前输入栏刚完成的紧凑化调整冲突。

### 方案 C：仅唤起系统键盘

代码最少且表情全集由系统维护，但 iOS 和 Android 不保证应用可以直接切换到系统 Emoji 页，用户通常仍需手动切换输入法，因此不符合“一键选择常用表情”的目标。

选择方案 A。

## 组件边界

新增独立的 `EmojiPicker` 组件，职责仅包括：

- 渲染固定的常用 Emoji 列表；
- 把用户选择的 Emoji 通过回调上报；
- 提供退格按钮并通过回调上报；
- 提供稳定的无障碍标签和可滚动宫格。

`ChatScreen` 负责面板显隐、系统键盘互斥、草稿更新和光标位置。输入框外层改为可容纳尾部笑脸按钮的容器，但不改变添加、语音和发送按钮的现有尺寸。

文本编辑规则抽成无 UI 依赖的纯函数，接收当前文本、选择范围和插入或删除动作，返回新文本与新光标位置。这样 Emoji 面板不直接依赖提及、引用或发送逻辑。

## 输入栏与面板布局

输入框外观继续沿用当前圆角、边框和背景色。笑脸按钮位于输入框内部右侧，视觉尺寸为 36×36，点击热区保持至少 44×44。文本输入区增加右侧内边距，保证文字和按钮不重叠。

Emoji 面板位于输入栏下方、底部安全区上方，像系统键盘一样向上占用聊天页空间。面板使用页面表面色和顶部细边框，高度固定为 240dp。宫格为 8 列，单元格至少 44×44，可上下滚动；常用列表约 80 个，覆盖笑脸、手势、爱心、庆祝、动物、食物和常用符号。右下区域提供图标库中的退格按钮，不使用文本符号或手绘图标。

面板不包含分类栏、搜索栏或最近使用记录，避免在“常用表情”范围外增加状态和存储。

## 交互与状态流

聊天页新增 `emojiPickerVisible` 状态。

点击笑脸按钮时：

1. 如果面板未打开，先退出语音模式并让输入框失焦，调用系统键盘收起操作，再显示 Emoji 面板。
2. 如果面板已打开，关闭面板并重新聚焦输入框，恢复系统键盘。

点击输入框、切换语音模式、发送成功、切换会话或离开页面时关闭 Emoji 面板。打开附件选择器时也关闭面板，避免两个底部区域同时存在。

面板显示期间保留当前草稿和选择范围。选择 Emoji 后不自动关闭面板，用户可以连续输入；发送按钮根据现有 `draft.text.trim()` 规则立即启用。

## 插入与退格规则

插入 Emoji 时：

- 没有选区：插入当前光标位置，光标移动到 Emoji 之后；
- 有选区：用 Emoji 替换选区，光标移动到 Emoji 之后；
- 选择范围越界：先夹紧到文本边界，避免运行时错误。

更新草稿时继续经过现有 `applyMentionTextChange`，确保在 @提及文本内部插入或替换会正确清理失效的提及元数据。引用草稿独立保存，不受 Emoji 编辑影响。

退格时：

- 有选区：删除整个选区；
- 无选区且光标大于 0：删除光标前一个完整 Unicode 字素簇，而不是单个 UTF-16 码元；
- 光标位于文本开头：不做修改。

字素簇处理优先使用运行时 `Intl.Segmenter`；若运行时不支持，则使用覆盖常见 Emoji 组合、变体选择符、肤色修饰符、区域旗帜和零宽连接序列的本地回退函数，避免留下半个 Emoji 或无效代理项。

## 错误与兼容处理

- Emoji 是普通 Unicode 文本，沿用现有 TEXT 消息发送、同步、引用和重发流程，不增加服务端字段或数据库迁移。
- 面板使用 React Native 基础组件和现有 Ionicons，不增加 npm 依赖。
- 系统键盘收起是异步行为；面板显隐不依赖键盘事件完成，避免部分 Android 输入法不回调时无法打开。
- 面板打开期间如果应用进入后台或页面卸载，状态随页面生命周期清理，不持久化。
- 输入框的最大高度、换行和现有 @提及选择规则保持不变。

## 验证

按用户约定不新增或运行自动化测试，只执行移动端 TypeScript 检查、相关文件 ESLint 和 `git diff --check`。

手动验收覆盖：

1. 点击输入框内笑脸，系统键盘收起并显示 Emoji 面板；再次点击切回系统键盘。
2. 面板显示后输入栏宽度和外部添加、语音、发送按钮位置稳定，无重叠或横向溢出。
3. 单击和连续点击 Emoji 均插入当前光标位置，光标落在新 Emoji 后。
4. 选中文字后点击 Emoji，选区被替换且其余文字保持不变。
5. 退格可删除选区、普通字符、变体 Emoji、肤色 Emoji、旗帜和零宽连接 Emoji，不留下乱码。
6. 在 @提及内部插入、替换或删除时，失效的提及元数据被正确移除；引用草稿保持不变。
7. 发送消息、切换语音、打开附件、切换会话和离开页面后面板关闭。
8. iOS 与 Android 上宫格可滚动，表情显示正常，退格和笑脸按钮的读屏标签正确。
