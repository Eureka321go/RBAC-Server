# IM 客户端消息免打扰设计

## 目标

为单聊和群聊提供账号级、会话级的消息免打扰设置。设置由服务端持久化并随会话快照同步，客户端在会话列表展示状态。开启免打扰后仍接收和存储消息，保留未读数字与“有人@我”提醒。

本轮不接入新的系统通知能力。后续实现系统通知时，通知发送或展示链路必须依据同一 `muted` 状态过滤。

## 交互

- 会话列表不承载免打扰设置入口，也不响应会话长按操作。
- 单聊从聊天页右上角进入“会话设置”，群聊复用现有“群设置”页面。
- 设置页使用开关切换消息免打扰，执行期间禁用重复提交。
- 操作成功后开关和会话列表立即刷新。
- 开启免打扰的会话在列表展示静音图标，但未读数字和“有人@我”提示保持不变。
- 更新失败时保留原状态并显示中文错误，不制造客户端与服务端不一致的假成功状态。
- 点击会话仍按原逻辑进入聊天页面。
- 后续“置顶聊天”使用相同的设置页入口，不在本轮提前实现置顶字段或排序。

## 服务端

`im_conversation_member.muted` 是当前用户在会话中的个人设置，`0` 表示正常，`1` 表示免打扰。

新增当前用户设置接口：

```text
PUT /im/conversations/{cid}/mute
{ "muted": true }
```

接口从登录上下文取得用户 ID，不接受客户端指定操作者。服务层必须确认该用户仍是会话成员，只更新匹配 `cid + userId` 的成员行。请求字段缺失返回参数错误；会话不存在或用户不是成员时返回业务错误。

`GET /im/conversations` 的每项快照新增布尔字段 `muted`。服务端从当前用户自己的成员行生成该字段，空值按 `false` 处理，不读取其他成员的设置。

## SDK Core 与本地存储

SQLite `conversations` 表新增 `muted INTEGER NOT NULL DEFAULT 0` 迁移。`ConversationRow` 暴露 `muted: boolean`。

全量会话同步把服务端 `muted` 写入本地快照。与消息序号不同，免打扰是可双向切换的设置，快照必须以服务端值覆盖本地值，不能使用只增不减合并。

SDK 新增 `setConversationMuted(cid, muted)`：

1. 调用服务端设置接口。
2. 服务端成功后更新目标 SQLite 行的 `muted`。
3. 发出既有 `conversation` 事件，让列表从 SQLite 重读。
4. 任一步失败均向调用方抛出错误；接口失败时不修改本地状态。

如果服务端已成功但本地写入异常，下次全量同步会以服务端快照修正。本轮不增加离线设置队列。

## 移动端

聊天页为单聊和群聊统一展示右上角设置按钮：单聊进入独立“会话设置”页，群聊进入现有“群设置”页。两个设置页都从 SDK SQLite 读取当前 `muted`，监听既有 `conversation` 事件刷新，并通过 `setConversationMuted` 更新。

设置成功后开关立即刷新；失败时保留原状态并显示中文错误。会话列表只根据 `row.muted` 展示静音图标和无障碍描述，不包含长按设置逻辑。

## 边界与安全

- 单聊和群聊使用同一接口与数据模型。
- 免打扰只属于当前账号，不影响其他成员。
- 免打扰不改变消息接收、SQLite 持久化、会话排序、未读数、已读水位、@ 提醒或消息发送。
- 服务端不信任客户端传入的用户身份，并以会话成员关系作为更新边界。
- 不输出会话正文或账号隐私到日志。
- 保留工作区中已有的后端注释改动，不将其纳入本功能提交。

## 验证

按约定不新增或运行自动化测试，只执行后端跳过测试的编译、SDK Core 与移动端 TypeScript 检查、相关文件 ESLint 和 `git diff --check`。

手动验收覆盖：

1. 单聊从聊天页右上角进入“会话设置”，群聊从右上角进入“群设置”，两处均可开启、取消免打扰。
2. 会话列表普通点击仍能进入聊天，长按不弹出免打扰菜单。
3. 设置成功后列表图标立即变化，刷新、重进和重新登录后仍保持。
4. 开启免打扰后新消息仍到达，未读数字与“有人@我”仍正常。
5. 另一账号的同一会话状态不受影响。
6. 断网或服务端拒绝时显示中文错误，图标和真实状态不发生假变化。
