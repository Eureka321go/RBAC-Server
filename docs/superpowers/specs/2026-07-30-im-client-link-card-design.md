# IM 客户端链接卡片设计

## 背景与目标

后端已经完成文本消息首个 `http(s)` 链接的异步 Open Graph 抓取：文本消息先按原链路落库和推送，抓取成功后把卡片写入 MongoDB 的 `body.link`，再扇出 `LINK_PREVIEW` 增量帧。客户端当前不识别该帧，也不渲染同步消息中已有的 `body.link`。

本轮目标是在不阻塞文本发送、不改变消息序号语义的前提下，让单聊和群聊能够实时、持久地展示链接卡片。点击卡片使用系统默认浏览器打开。首版不加载第三方缩略图，避免客户端自动请求不可信图片地址。

## 范围

本轮包含：

- SDK Core 识别并持久化合并 `LINK_PREVIEW` 增量帧。
- SDK Core 对增量卡片做严格结构校验并处理乱序与重复帧。
- React Native 聊天页展示同步消息或增量消息中的合法卡片。
- 点击卡片时只允许通过系统浏览器打开 `http:` 或 `https:` 地址。
- 抓取、同步、字段或打开失败时安全降级为原文本消息。

本轮不包含：

- 修改后端链接抓取、缓存和 SSRF 防护实现。
- 展示或请求 `link.image`，以及后端图片代理或对象存储缓存。
- App 内置浏览器、WebView 或网页登录态共享。
- 一条消息展示多张卡片。
- 客户端自行抓取网页或手动刷新卡片。
- 新增独立 `LINK` 消息类型；链接卡片仍属于 `TEXT` 消息正文的补充元数据。

## 服务端契约

后端对 `TEXT` 正文提取首个 `http(s)` URL。抓取成功后发送：

```json
{
  "op": "LINK_PREVIEW",
  "cid": "s:1:2",
  "seq": 42,
  "body": {
    "link": {
      "url": "https://example.com/article",
      "title": "文章标题",
      "description": "可选描述",
      "image": "https://example.com/cover.jpg",
      "siteName": "Example"
    }
  }
}
```

其中 `url` 和 `title` 是客户端展示所需字段；`description` 与 `siteName` 可缺省；`image` 即使存在也必须忽略。REST 增量同步可能直接在原 `TEXT` 消息的 `body.link` 中返回同一结构。

## SDK 架构与数据流

协议层新增只接收的 `LINK_PREVIEW` 操作码。它是原消息的增量元数据，不是新消息，不得推进 `synced_seq`、会话 `last_msg_seq`、未读数、已读位点或会话排序。

`ChatService` 收到该帧后交给 `SyncEngine.applyLinkPreview`。同步引擎校验：

- `cid` 是非空字符串。
- `seq` 是正安全整数。
- `body.link` 是对象。
- `url` 是可解析的绝对 URL，协议只能是 `http:` 或 `https:`。
- `title` 是去除首尾空白后的非空字符串。
- `description` 与 `siteName` 只有在为字符串时才保留，并去除首尾空白；空字符串按缺省处理。
- 字段在客户端再次限制长度：`url` 最多 2048 个 UTF-16 代码单元、`title` 和 `siteName` 最多 200 个、`description` 最多 300 个；超长可选字段裁剪，超长 URL 或空标题使整张卡片无效。

协议增量和 REST 同步共用一个纯函数完成上述规范化。规范化结果只包含 `url`、`title`、可选 `description` 和可选 `siteName`。客户端不保留也不使用 `image` 或未知字段；REST 消息的其他正文键保持不变。

`MessageStore` 按 `cid + seq` 读取目标消息。只有目标存在、类型为 `TEXT` 且尚未撤回时，才在 TypeScript 中把规范化卡片合并到原正文：

```ts
{ ...originalBody, link: normalizedLink }
```

随后更新该行的 `body_json`。这样不会覆盖 `text`、`mentions` 或其他正文数据，也不依赖 SQLite JSON 扩展。重复帧覆盖同一个 `body.link`，操作天然幂等。非文本目标、已撤回目标、损坏正文和畸形卡片均静默忽略。

正常服务端顺序是先推送原消息，再推送卡片。为防御极少数网络乱序，同步引擎按 `cid + seq` 在内存暂存先到的合法卡片；原消息落库时立即合并并清除暂存项。暂存不作为 UI 数据源，最多保留 100 项和 60 秒，超出容量时淘汰最早项。若应用退出、暂存过期或被淘汰，后端 MongoDB 已保存卡片，之后 REST 同步会返回完整正文，因此无需新增持久化表。

卡片成功落库后只发出该 `cid` 的 `message` 事件，让已打开的聊天页从 SQLite 重新读取。它不发出会改变会话摘要语义的增量数据；会话列表继续显示原文本摘要。

## 移动端展示与交互

新增独立的链接卡片解析与展示边界。聊天页对 `TEXT` 消息仍先用现有 `MentionText` 显示原正文；当 `body.link` 通过同一规范化规则后，在正文下方追加一张卡片。

卡片内容如下：

- 第一行显示 `siteName`；缺省时从 `url` 提取主机名。
- 标题最多两行，使用正文强调字重。
- 描述存在时最多两行，使用次要文字颜色。
- 不读取、不预加载、不渲染 `image`。
- 使用现有主题中的弱背景、边框、圆角和间距，己方与对端布局一致。

卡片是可点击区域，并提供包含标题或域名的无障碍标签。外层消息气泡继续负责长按撤回；卡片点击和消息长按不改变现有两分钟撤回判断。

点击时再次解析目标 URL，只允许 `http:` 或 `https:`，然后调用 React Native `Linking.openURL` 交给系统默认浏览器。解析失败、系统无法处理或打开抛错时，聊天页显示“无法打开此链接”的中文提示。客户端不尝试改写协议，也不把失败地址交给其他原生能力。

## 一致性与失败降级

- 后端抓取失败、超时、负缓存命中或线程池丢弃：消息保持纯文本。
- 卡片增量迟到：原消息先正常展示，成功合并后刷新为正文加卡片。
- 客户端离线：之后同步到带 `body.link` 的原消息时直接展示。
- 增量帧重复：覆盖同一个字段，不生成新消息或重复卡片。
- 增量帧早于原消息：暂存并在原消息落库时合并。
- 卡片字段畸形或 URL 协议不安全：忽略卡片，原文本照常展示。
- 目标消息已经撤回：拒绝补写；撤回正文清空后卡片也随之消失。
- `@` 提及与链接共存：只追加 `body.link`，不改变 `text` 和 `mentions`，现有高亮保持不变。
- 系统浏览器打开失败：仅显示错误提示，不删除或修改卡片。

## 验证方式

按项目约定，本轮不新增或运行自动化测试。实现后只执行 TypeScript 类型检查、现有 ESLint 和 `git diff --check`；若现有检查出现与本轮无关的问题，单独说明，不扩大修改范围。

用户手测至少覆盖：

1. 发送含一个链接的文本，正文先出现，卡片随后补上。
2. 卡片显示站点名或域名、标题和可选描述，不请求缩略图。
3. 点击卡片由系统默认浏览器打开最终 `http(s)` 地址。
4. 一条文本含多个链接时只显示首个链接的卡片。
5. 单聊、群聊和双方实时接收表现一致。
6. 离线后重新同步、退出聊天页再进入，卡片仍存在。
7. 抓取失败、无标题、非法协议和字段畸形时只显示原文本。
8. 卡片到达后仍可长按撤回；撤回后正文与卡片都不再显示。
9. `@` 提及与链接在同一文本中时，高亮和卡片互不影响。
10. 重复增量帧不生成重复卡片，也不改变未读数和会话排序。

## 完成标准

SDK 能将实时 `LINK_PREVIEW` 安全、幂等地合并进 SQLite 原消息，REST 同步携带的卡片使用相同验证规则；移动端稳定展示无缩略图卡片并通过系统浏览器打开合法链接；任何失败都降级为可读的原文本，且不改变现有发送、提及、撤回、已读和会话排序语义。
