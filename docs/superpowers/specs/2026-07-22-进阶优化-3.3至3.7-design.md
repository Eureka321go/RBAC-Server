- 依赖:Spring Boot 3.4.1 + Security + data-redis(Lettuce) + MyBatis-Plus 3.5.9 + Flyway + MySQL 8.4。**无** actuator / spring-cache / shedlock / resilience4j / springdoc。

## 2. 分主题设计

### 3.3 可观测性与健康检查

**依赖**:`spring-boot-starter-actuator`。

**改动**:
1. `application.yml` 公共段开启端点:`management.endpoints.web.exposure.include=health,info,metrics,prometheus`;`management.endpoint.health.probes.enabled=true`;`management.endpoint.health.show-details=when-authorized`;`info` 注入 `build`/`git`(可选 `spring.info` 属性)。
2. 新增 `common/observability/RedisHealthIndicator`(或复用自动配置的 redis 健康检查 + 自定义补充):Redis `PING` 失败 → 组件 DOWN,呼应"Redis 不可用时登录/权限会怎样"。
3. `common/observability/WorkflowMetrics`:用 `MeterRegistry` 对审批埋点——`workflow.approve.timer`(耗时,`@Timed` 或手动 `Timer.Sample`)、`workflow.approve.count{result=success|fail}`;登录成功/失败 `Counter`(接到认证成功/失败 handler)。
4. `SecurityConfig`:放行 `/actuator/health/**`(readiness/liveness 供容器探针无鉴权访问);其余 actuator 端点要求 `hasAuthority('monitor:view')`(新增权限码,super_admin 天然拥有)。端点路径在 `/api` context-path 下,即 `/api/actuator/**`。

**文档要点**:health vs readiness/liveness、show-details 的鉴权、Micrometer 指标类型(Counter/Timer/Gauge)、生产为何要保护管理端点。

### 3.4 缓存设计(Spring Cache 抽象)

**依赖**:`spring-boot-starter-cache`(Redis starter 已在)。

**改动**:
1. 新增 `common/config/CacheConfig`:`@EnableCaching` + `RedisCacheManager`;value 用 JSON 序列化(`GenericJackson2JsonRedisSerializer`),按 cacheName 配独立 TTL(如 `userPerms` 30 分钟),key 前缀统一 `rbac:cache:`。
2. 新增 `system/menu/service/PermissionCacheService`(或放 menu 模块内):方法 `Set<String> loadUserPermissions(Long userId)` 与 `List<String> loadAllPermissions()`,分别 `@Cacheable(cacheNames="userPerms", key="#userId")` / `@Cacheable("allPerms")`。
3. `LoginUserAssembler#assemble` 改为调用 `PermissionCacheService`,不再直连 mapper 查权限。
4. **精准失效**:
   - 角色分配菜单/改权限 → 该角色下所有用户的 `userPerms` 失效(先查角色关联用户 id,逐个 `@CacheEvict`,或用 `allEntries` 简化并在文档说明取舍)。
   - 用户改角色、角色启停 → 失效相关用户。
   - 说明放在 `RoleService`、用户角色维护处;超管权限变化额外清 `allPerms`。
5. 防护:`userPerms` 允许缓存空集合(缓存穿透),TTL 加随机抖动(雪崩),文档讲清 Cache Aside 与穿透/击穿/雪崩。

**注意**:改密/登出/强退后权限缓存不能影响"旧 Token 失效"红线——Token 失效仍由 `TokenSessionService` 黑名单负责,权限缓存只影响"新请求拿到的权限集",二者正交,文档需点明。

**文档要点**:`@Cacheable/@CachePut/@CacheEvict`、Cache Aside、穿透/击穿/雪崩/热 Key、哪些权限可缓存哪些必须实时。

### 3.5 定时任务与可靠后台任务

**依赖**:`net.javacrumbs.shedlock:shedlock-spring` + `shedlock-provider-redis-spring`。

**改动**:
1. Flyway `V3__shedlock.sql`:若用 JDBC provider 需建 `shedlock` 表;**采用 Redis provider 则免表**(优先 Redis provider,少一张表,和现有 Redis 基建一致)。> 决策:用 Redis provider,不新增表;`V3` 视需要保留占位或不创建。
2. 新增 `common/schedule/ScheduleConfig`:`@EnableScheduling` + `@EnableSchedulerLock(defaultLockAtMostFor="PT5M")`,注入 `RedisLockProvider`。
3. 新增 `common/schedule/TokenCleanupJob`:定时清理 Redis 中已过期的会话/黑名单残留键(若 Redis 已靠 TTL 自动过期,则任务改为"统计并记录会话数"或"清理索引集合中的失效引用",保证任务有真实意义)。`@Scheduled(cron=...) @SchedulerLock(name="tokenCleanup")`。
4. 新增 `workflow/task/schedule/OverdueTaskScanJob`:扫描超过阈值(如 3 天,阈值走配置)未处理的 `wf_process_task`,打"超时"标记 / 记一条提醒日志。**幂等**:只对未标记的置标,重复执行不产生副作用;`@SchedulerLock` 保证多实例单跑。阈值加入 `RbacProperties`(如 `rbac.workflow.overdue-days`)。

**文档要点**:固定频率 vs Cron、多实例为何重复执行、ShedLock 原理(锁记录 + lockAtMostFor/lockAtLeastFor)、幂等设计、何时升级到调度平台/MQ。

### 3.6 API 文档与兼容性

**依赖**:`org.springdoc:springdoc-openapi-starter-webmvc-ui`(适配 Spring Boot 3 / Swagger UI)。

**改动**:
1. 新增 `common/config/OpenApiConfig`:`OpenAPI` bean——标题/版本/描述;`SecurityScheme` `bearerAuth`(HTTP bearer, JWT),全局 `SecurityRequirement`;`GroupedOpenApi` 分组(如 `auth`、`system`、`workflow`)。
2. 给示范 controller 补注解:`auth`(登录/刷新)+ 1~2 个系统模块(如 user 或 role)加 `@Tag`/`@Operation`/`@ApiResponse`/`@Schema`;统一错误响应用 `Result` 结构示例。其余保持,文档说明"按此模式补全"。
3. `SecurityConfig`:放行 `/v3/api-docs/**`、`/swagger-ui/**`、`/swagger-ui.html`(注意 `/api` context-path,访问路径为 `/api/swagger-ui/index.html`)。**生产环境可关闭**:`springdoc.api-docs.enabled` 在 `application-prod.yml` 设 `false`,文档说明取舍。

**文档要点**:OpenAPI 契约价值(而非只生成页面)、JWT 安全方案接入、字段兼容/弃用策略、生产是否暴露文档。

### 3.7 稳定性设计

**依赖**:`io.github.resilience4j:resilience4j-spring-boot3`(用于 `@RateLimiter`)。

**改动**:
1. **优雅停机**:`application.yml` 加 `server.shutdown=graceful` + `spring.lifecycle.timeout-per-shutdown-phase=20s`;文档讲停机流程(停止 accept 新请求 → 放完在途请求 → 关线程池,与 3.2 异步日志线程池 `waitForTasksToCompleteOnShutdown` 呼应)。
2. **超时**:显式配置——Redis Lettuce `spring.data.redis.timeout` / `connect-timeout`;HikariCP `spring.datasource.hikari.connection-timeout`。文档区分连接超时 / 读取超时 / 总超时。
3. **幂等**:新增 `common/idempotent/@Idempotent` 注解 + `IdempotentAspect`(AOP):读取请求头幂等键(如 `Idempotent-Key`)或按方法+用户+参数指纹,`Redis SETNX` 占位(短 TTL),命中重复 → 抛 `BusinessException`(明确业务错误码)。接到工作流"发起流程"`InstanceController` 与"审批"`TaskController`。前端禁用按钮只是体验,后端才是红线。
4. **限流**:Resilience4j `@RateLimiter(name="login")` 接到登录接口(防暴力破解),`application.yml` 配 `resilience4j.ratelimiter.instances.login`;超限返回统一错误(接 `GlobalExceptionHandler` 处理 `RequestNotPermitted`)。
5. **熔断/重试**:仅文档讲原理与适用场景,不落代码(YAGNI:当前无不稳定外部依赖)。

**文档要点**:各类超时、可重试 vs 会重复写入、幂等键/唯一约束/防重复提交、限流/熔断/降级/隔离区别、优雅停机与在途事务。

## 4. 影响面与红线检查

- **安全红线**:actuator 敏感端点鉴权、swagger 生产可关;权限缓存不破坏"旧 Token 失效";幂等/限流后端强校验;日志不泄密(埋点只记指标,不带敏感参数)。
- **改动集中在 `common/` 与各模块少量接入点**,不做无关重构。
- **配置**:新增项分环境放置(超时、限流参数、文档开关、超时待办天数)。
- **DB**:优先 Redis provider,力争不新增表;若用 JDBC provider 才加 `V3`。

## 5. 验收标准

1. `mvn -f backend/pom.xml package` 通过;应用可启动。
2. `/api/actuator/health` 可访问且含 redis 组件;敏感端点未授权返回 403。
3. 登录后 `userPerms` 命中缓存;角色改权限后对应用户缓存失效、下次请求拿到新权限。
4. 定时任务在单实例正常执行,多实例下 `@SchedulerLock` 只跑一个(文档给出验证方法)。
5. `/api/swagger-ui/index.html` 打开,登录接口可"Authorize"后调用。
6. 同一幂等键重复提交"发起流程/审批"被拒;登录接口超限被限流。
7. `kill` 应用时优雅停机、在途请求/异步日志不丢(文档给验证步骤)。
8. `12`~`16` 五篇学习文档齐全,结构统一。
