# IM 客户端全局视觉改造设计

## 视觉基准

目标是将现有 React Native IM 客户端统一为克制、清晰、接近原生即时通讯产品的蓝白视觉。业务功能、接口、导航层级和本地数据结构保持不变。

## 全局设计语言

### 颜色

- 页面底色使用接近 `#F5F7FB` 的浅灰蓝。
- 主内容表面使用白色。
- 主品牌色使用 `#2F6BEE` 附近的稳定蓝色，不使用渐变。
- 主文字使用深蓝黑，次级文字使用蓝灰色。
- 分隔线使用低对比度冷灰。
- 成功、警告、危险状态只在需要表达状态时使用；危险操作不使用大面积粉红底色。

### 形态与间距

- 页面水平留白 16–20；内容区使用 8 的倍数建立节奏。
- 分组表面圆角 12–16，不嵌套卡片，不滥用阴影。
- 普通列表依靠留白和细分隔线区分，不给每一行单独套卡片。
- 所有主要点击区域至少 44×44。
- 标题、正文和辅助文字形成三级层次，正文保持 14–16。

### 图标与头像

- 用户继续使用稳定颜色的姓名首字符头像。
- 群聊继续使用固定群组图标，不改为群名首字符。
- 返回、添加、更多、编辑、删除等功能图标使用同一套矢量图标库，不使用文本符号、Emoji 或手绘 View 图形。
- 图标本身不承载唯一含义，关键操作同时提供可访问性标签或文字。

### 公共组件

- 建立统一设计 token：颜色、间距、圆角、字体尺寸。
- 提供主按钮、次按钮、危险按钮、文本输入框、图标按钮、分组表面和状态提示组件。
- `CompactScreenHeader` 统一为白底、无重阴影、细分隔线、44 点击区。
- `ConnectionStatusBar` 改成低高度、低饱和状态条，避免抢夺页面主标题的视觉权重。

## 页面改造

### 登录

- 使用简洁欢迎标题和说明，不再只有孤立的“IM 登录”。
- 输入框使用统一白色表面、清晰标签和聚焦边框。
- 登录按钮使用完整宽度主按钮，并补充提交中禁用反馈。
- 错误提示使用统一状态表面。

### 会话列表

- 顶部保留当前用户头像与身份，但降低工具栏拥挤度。
- “单聊”“群聊”改成统一图标按钮或轻量文字按钮。
- 会话列表放在单一白色分组表面中，头像、标题、预览、时间/状态和未读数对齐。
- 群聊固定群图标，单聊使用联系人首字符头像。

### 通讯录

- 部门面包屑、部门行和成员行使用同一列表体系。
- 部门行使用图标、名称、人数和进入箭头；成员行使用头像、姓名和用户 ID。
- 多选状态使用清晰圆形勾选控件，不用大面积背景表示唯一状态。
- 手工 userId 输入作为失败回退，放在次要折叠式或弱化区域。

### 创建群聊

- 群名称作为明确的第一步输入。
- 已选人数成为区段标题的一部分。
- 通讯录选择区使用统一白色分组表面。
- 创建按钮固定为清晰主操作，错误/加载状态使用统一反馈。

### 聊天

- 保持现有消息方向、头像、人名、已读状态和加倍后的消息间距。
- 页面底色、标题栏和输入区切换到统一视觉 token。
- 输入区使用白色表面、圆角文本框和品牌色发送按钮。
- 系统消息、失败重试和连接错误保持低噪音但可识别。

### 群资料

- 以选定方案为直接参考：顶部居中固定群头像、群名、群号、人数和当前角色。
- 群名称改为设置行；点击后打开编辑弹窗，不常驻显示输入框。
- 成员区显示标题、人数和添加成员入口。
- 成员行显示首字符头像、姓名、角色/禁言状态和右侧更多按钮。
- 点击更多按钮打开底部操作面板，根据权限显示设/免管理员、禁言/解禁、转让群主和移出群聊。
- 当前用户不显示无效管理菜单。
- 解散/退出群聊放在独立危险设置行，保留二次确认。
- 添加成员弹窗沿用新的面板、按钮、输入框和通讯录样式。

## 交互与状态

- 所有原有权限判断和请求函数继续复用，不改变服务端行为。
- 成员管理面板在请求执行前关闭或进入明确加载状态，防止重复提交。
- 改名、添加成员、危险操作继续显示现有确认和错误信息。
- 加载、空状态、接口失败和按钮禁用均使用统一视觉反馈。
- 文本不得被操作按钮挤压；小屏时优先保证姓名、角色和主操作可读。

## 技术边界

- 仅修改 `app-mobile` 展示层和必要的前端依赖。
- 不修改后端接口、SDK 协议、本地数据库和导航路由。
- 不生成真实人物头像，不新增上传能力。
- 引入一套适配 React Native 的矢量图标依赖，替换现有文字图标与手工群图形。
- 沿用当前 `feat/im` 分支，不推送远端。

- 人工覆盖登录、会话、通讯录、建群、聊天、群资料及两个底部面板的主要交互。
