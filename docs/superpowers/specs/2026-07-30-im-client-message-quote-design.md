# IM 消息引用设计

## 背景

当前 IM 客户端已经支持文本、图片、文件、语音、链接卡片、撤回、群聊提及和已读回执，但不能针对某条消息发送上下文明确的回复。本期增加单层消息引用：用户可引用一条已落库的文本、图片、文件或语音消息，并发送一条带引用块的文本消息。

消息引用、会话免打扰和置顶聊天拆成三个独立迭代。本设计只覆盖消息引用，不修改会话偏好或会话列表排序。

## 目标

- 单聊和群聊均可引用已落库、未撤回的文本、图片、文件和语音消息。
- 引用后只发送文本回复，不改变图片、文件和语音上传协议。
- 服务端校验目标并生成权威引用快照，客户端不能伪造引用发送者或内容。
- 发送中、实时推送、离线同步和失败重试使用一致的引用结构。
- 点击引用块时，已在本地的原消息可被定位并短暂高亮。
- 原消息撤回后，既有引用块显示“原消息已撤回”，不再泄露快照摘要。
- 引用与提及、链接卡片、撤回和已读链路互不干扰。

## 非目标

- 不支持嵌套引用链或一次引用多条消息。
- 不支持图片、文件或语音消息自身携带引用。
- 不连带实现历史消息回溯；目标不在本地时只给出提示。
- 不支持引用本地待发送消息、系统消息、撤回控制消息或链接预览增量帧。
- 不修改原消息，也不建立独立的回复关系表或新消息类型。

## 方案选择

采用“客户端提交目标序号，服务端校验并生成快照”的方案。

只保存 `targetSeq` 会使离线或本地缺失时无法稳定展示。新增独立回复消息类型和关系表则会扩大定序、存储和查询边界，不符合当前单层引用需求。服务端快照既能独立展示，又能通过 `targetSeq` 定位原消息，并避免信任客户端提供的发送者和摘要。

## 协议与数据结构

带引用的回复仍使用 `type=TEXT`。客户端发送的正文示例：

```json
{
  "text": "我的回复",
  "quote": {
    "targetSeq": 42
  }
}
```

客户端 outbox 可以暂存完整的本地预览，以便最终 `PUSH` 到达前渲染发送中气泡。服务端只读取 `quote.targetSeq`，忽略并覆盖客户端提供的其他引用字段。

服务端落库和下发的权威结构如下：

```json
{
  "text": "我的回复",
  "quote": {
    "targetSeq": 42,
    "senderId": 1001,
    "senderName": "张三",
    "type": "FILE",
    "summary": "项目计划.pdf"
  }
}
```

字段约束：

- `targetSeq`：同一会话内被引用消息的正整数序号。
- `senderId`：目标消息的真实发送者 ID。
- `senderName`：引用发生时服务端解析出的展示名，最多 80 个 Unicode 码点；缺失时使用稳定的用户 ID 兜底文案。
- `type`：只允许 `TEXT`、`IMAGE`、`FILE` 或 `AUDIO`。
- `summary`：服务端生成的单行摘要，最多 120 个 Unicode 码点，并清除控制字符。

摘要规则：

- `TEXT`：只取目标消息自己的 `body.text`，折叠换行与连续空白；空内容回退为 `[文本]`，不递归拼接其 `body.quote`。
- `IMAGE`：固定为 `[图片]`。
- `FILE`：对文件名取 basename、清除控制字符并折叠空白，缺失时为 `[文件]`。
- `AUDIO`：固定为 `[语音]`。

## 服务端处理

新增职责单一的 `QuoteService`，在 `InboundMessageConsumer` 完成幂等、成员、禁言和媒体检查后、提及解析与消息定序前处理 `TEXT` 正文。

处理顺序：

1. `body.quote` 缺失时原样返回，不影响普通文本消息。
2. 校验 `targetSeq` 为正 64 位整数；客户端同时限制在 JavaScript 安全整数范围内。
3. 使用 `cid + targetSeq` 查询 MongoDB，确保目标属于当前会话。
4. 拒绝不存在、已经撤回或类型不受支持的目标。
5. 批量用户资料能力解析目标发送者展示名。
6. 根据目标类型构造长度受限的权威快照。
7. 复制原正文并用权威快照覆盖 `body.quote`，再进入提及校验、定序、落库和扇出。

同一会话的发送与撤回沿现有 Kafka 分区顺序处理。若撤回先被处理，新引用会因目标已撤回而失败；若引用先落库，之后的撤回通过 `RECALL targetSeq` 让客户端隐藏引用摘要。

服务端新增错误码：

- `QUOTE_TARGET_INVALID`：目标序号格式错误。
- `QUOTE_TARGET_NOT_FOUND`：目标不存在或不属于当前会话。
- `QUOTE_TARGET_RECALLED`：目标已经撤回。
- `QUOTE_TARGET_UNSUPPORTED`：目标消息类型不可引用。

引用校验失败时，整条回复不定序、不落库，并通过现有 `ERROR` 帧返回发送方。

## SDK Core

新增独立的引用载荷模块，负责以下职责：

- 定义客户端引用预览和服务端权威快照类型。
- 从用户选择的本地消息构造单层预览。
- 在 `buildTextMessageBody` 中把引用与 `mentions`、`mentionAll`、`mentionRanges` 合并。
- 合法化实时推送、离线同步和 outbox 中的引用数据。
- 对畸形、超长或不支持类型的引用返回空值，仅忽略引用块，不丢弃文本正文。

`SendTextOptions` 新增可选 `quote`。outbox 保存完整本地预览，因此 ACK/PUSH 超时后的原 `clientMsgId` 重试会保留引用。最终 `PUSH` 落库后，现有结算链使用服务端快照替换发送中数据。

`normalizeTextMessageBody` 同时规范化 `text`、`mentions`、`link` 和 `quote`。链接预览异步补写只更新 `body.link`，不得覆盖 `body.quote`。

## 移动端交互

### 选择引用

`MessageActionSheet` 对已落库、未撤回且类型受支持的消息显示“引用”。本地待发送消息、系统消息和控制消息不显示该操作。

选择后，聊天输入框上方显示引用预览：发送者名称、类型图标和单行摘要。关闭按钮只取消引用，不清空已有文字草稿。选择图片、文件或进入语音模式不会消费引用状态；只有成功写入一条文本 outbox 或用户主动取消时才清除输入区引用。

### 展示引用

文本消息气泡在回复正文上方显示紧凑引用块。引用目标本身即使也带引用，只展示目标自己的发送者和内容摘要，不递归展示更早引用。

客户端维护现有撤回控制消息形成的 `targetSeq` 集合。若引用目标已撤回，引用块只显示“原消息已撤回”，不展示原发送者和摘要，也不可点击定位。

### 定位原消息

点击有效引用块后：

- 当前本地消息列表存在相同 `seq` 时，调用列表定位能力滚动到目标，并用短时状态突出其气泡；高亮自动清除。
- 当前列表不存在目标时，显示“原消息暂未加载”，不发起网络请求。
- 列表定位失败不得导致页面崩溃；失败时降级为相同提示。

引用预览与消息气泡复用同一个展示组件，通过显示模式控制尺寸和关闭按钮，避免摘要规则和撤回占位出现两套实现。

## 与现有能力的关系

- 提及：回复正文继续使用现有 `mentions` 和 `mentionRanges`，引用摘要不参与提及高亮。
- 链接卡片：回复正文中的首个链接仍可异步生成 `body.link`，引用块与链接卡片分别展示。
- 撤回：撤回引用回复时，正文、引用块和链接卡片一并隐藏；撤回被引用目标时，引用回复保留但引用块变为撤回占位。
- 已读：引用不新增消息，不改变 seq、未读数或已读水位语义。
- 会话摘要：仍按回复正文生成，不把引用摘要拼进会话列表预览。
- 群成员变化：引用快照保留引用发生时的服务端展示名，成员之后退群不影响既有引用。

## 安全与容错

- 服务端不信任客户端提交的 `senderId`、`senderName`、`type` 或 `summary`。
- 查询始终包含当前 `cid`，避免跨会话探测或引用消息。
- 摘要和姓名均限制长度、折叠空白并清理控制字符，避免存储膨胀或界面异常。
- 畸形引用只影响引用块；合法的回复正文仍可被客户端展示。
- 目标正文只截取必要摘要，不复制媒体 URL、本地路径、对象存储键或嵌套引用。
- 错误提示使用固定中文映射，不向客户端透出数据库或解析异常细节。

## 验证边界

按当前协作约定，本期不新增或运行自动化测试。实现完成后只执行与改动相符的静态验证：SDK Core 与移动端 TypeScript 类型检查、后端跳过测试的编译检查、改动文件 ESLint 和 `git diff --check`。

用户手动验收覆盖：

1. 分别引用文本、图片、文件和语音并发送。
2. 取消引用不清空文字；选择媒体或切换语音模式不消费引用。
3. 点击引用可定位并短暂高亮本地原消息；本地缺失时显示中文提示。
4. 已撤回消息不能新引用；原消息后撤回时，既有引用显示撤回占位且不泄露摘要。
5. 引用回复发送失败后重试，引用信息不丢失且最终只产生一条消息。
6. 单聊、群聊、双方实时接收、接收方离线恢复和退出页面重进后的展示一致。
7. 回复正文同时包含提及和链接时，正文高亮、引用块和链接卡片互不影响。
8. 客户端伪造发送者或摘要时，服务端仍写入权威快照；畸形下行引用不阻断正文展示。
9. 撤回引用回复后，正文、引用块和链接卡片均不再展示。

## 完成标准

消息引用以普通 `TEXT` 消息的 `body.quote` 存储和同步；服务端按同会话目标生成不可伪造的单层快照；客户端支持选择、取消、发送中展示、失败重试、离线恢复、点击定位和撤回占位；任何引用失败或畸形数据均不得破坏现有文本、提及、链接、撤回和已读链路。
