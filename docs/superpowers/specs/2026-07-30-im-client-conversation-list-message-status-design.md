# IM 会话列表与消息状态设计

## 目标

修复会话列表时间并重新组织会话行与己方消息状态，使信息层级接近微信：用户能快速识别最新消息时间、未读数量和免打扰状态；发送中、发送失败和撤回中互斥展示且位置稳定。

本设计覆盖会话列表与聊天页消息状态，不改变消息发送协议、未读计算、已读回执或免打扰语义。

## 截图审查结论

用户提供的会话列表截图显示所有会话均为 `11:15`。代码确认列表读取 `ConversationRow.updatedAt`，而全量同步把它写成 `Date.now() - index`，因此显示的是同步时刻，不是最新消息时刻。

聊天截图中同一条失败消息同时出现转圈和红色失败图标。失败的 outbox 消息 `seq` 为 `null`，未撤回时 `recallingSeq` 也为 `null`；现有表达式 `recallingSeq === item.seq` 错把它判定为撤回中。当前子元素顺序又把状态图标放在气泡与己方头像之间，视觉关系错误。

截图只能确认视觉结果与静态层级，不能证明动态状态持续时间、点击热区和读屏顺序；这些需要手动交互验证。

## 方案比较

### 方案 A：显式最新消息时间（采用）

服务端会话摘要增加 `lastMsgTs`，追加消息时与消息本体使用同一个 epoch millisecond 时间戳更新。SDK SQLite 增加同名字段，并在实时推送、离线同步和会话快照中前向合并。

优点是字段语义明确，客户端无需猜测，未完整拉取消息时仍能正确显示；代价是需要 MySQL 与 SQLite 各增加一次迁移。

### 方案 B：复用会话 `updated_at`

改动较少，但审计字段可能被非消息操作更新，也依赖自动填充是否覆盖已存在的时间，无法长期保证它就是最新消息时间。

### 方案 C：客户端从本地消息表计算

无需服务端字段，但本地可能只保存部分历史或尚未完成增量同步，列表时间会缺失或回退；每次读取列表还需额外聚合。

选择方案 A。数据字段与视觉展示分开，后续置顶聊天也能使用稳定的最新消息时间排序。

## 最新消息时间数据流

### 服务端

`im_conversation` 新增：

```text
last_msg_ts BIGINT NOT NULL DEFAULT 0
```

迁移对 `last_msg_seq > 0` 的旧会话使用现有 `updated_at` 做一次尽力回填。新消息追加时，`MessageAppender` 生成一个 `ts`，同时写入 Mongo 消息、会话 `lastMsgTs` 和下行 PUSH，三处保持一致。

`GET /im/conversations` 的 `ImConversationVO` 新增 `lastMsgTs`。无消息会话返回 `0`。

### SDK Core

SQLite `conversations` 新增 `last_msg_ts INTEGER NOT NULL DEFAULT 0`，迁移后从本地 `messages` 表的 `MAX(ts)` 回填已有会话。

`ConversationRow` 新增 `lastMsgTs: number`。会话快照使用 `MAX(本地值, 服务端值)`，避免旧服务端回填值覆盖本地已知的准确消息时间。实时 PUSH 与 REST 消息应用时，`advanceConversation` 使用消息自带 `ts`，只在消息序号不旧于当前摘要时更新预览和时间。

会话列表按 `last_msg_ts DESC` 排序；无消息会话以本地 `updated_at` 作为次级稳定顺序，但 UI 不展示伪造时间。

## 会话列表视觉结构

每行保持现有头像、标题和摘要样式，但改成三个明确区域：

1. 左侧头像区：未读徽标绝对定位在头像右上角，数字超过 99 显示 `99+`。
2. 中间内容区：第一行标题，第二行最新消息摘要；`[有人@我]` 仍位于摘要前。
3. 右侧状态区：固定宽度并右对齐，第一行显示时间，第二行仅在免打扰时显示静音图标。

未读徽标不再占据整行右侧空间，时间和静音图标不会互相挤压。免打扰仍保留数字未读，符合此前确认的产品语义。

时间按设备本地时区格式化：

- 今天：`HH:mm`
- 昨天：`昨天`
- 最近七天：`周一` 至 `周日`
- 本年更早：`M/D`
- 跨年：`YYYY/M/D`
- 无最新消息时间：不显示

会话行无障碍标签继续包含标题、免打扰状态、消息摘要和未读数量。

## 聊天页消息状态

为每条消息先派生唯一视觉状态，优先级如下：

1. `failed`：红色失败按钮，可点击重新发送。
2. `uploading`：取消上传按钮。
3. `sending`、`acked`：小型转圈。
4. `recalling`：仅当 `item.seq != null && recallingSeq === item.seq` 时转圈。
5. 其他状态：不显示状态控件。

同一条消息最多渲染一个状态控件。己方消息顺序调整为：

```text
[状态控件] [消息气泡与已读状态] [己方头像]
```

状态控件位于气泡左侧，与气泡垂直居中，不再夹在气泡和头像之间。视觉图标保持紧凑，但失败与取消按钮的实际触摸区域至少为 44×44；无障碍标签分别为“重新发送”和“取消上传”。对方消息布局保持头像在左、气泡在右。

单聊的“已读／已发送”仍显示在己方气泡下方，本轮不改变其业务逻辑。

## 错误与兼容处理

- `lastMsgTs` 缺失、非有限数或小于等于 0 时不显示时间，不回退到同步时间。
- 服务端旧数据回填只是兜底；客户端已从消息表得到更晚时间时保留更晚值。
- 乱序旧消息不得覆盖更新的会话摘要或时间。
- 修复撤回判断时必须要求非空 `seq`，避免所有 outbox 消息被误判为撤回中。
- 重试失败消息沿用现有 SDK 流程，不新增另一套状态机。

## 验证

按用户约定不新增或运行自动化测试，只执行后端跳过测试编译、SDK Core 与移动端 TypeScript 检查、相关 ESLint、迁移检查和 `git diff --check`。

手动验收覆盖：

1. 不同最新消息时间的会话显示各自正确时间，并按最新消息排序。
2. 今天、昨天、一周内、本年和跨年的格式符合设计；无消息会话不显示时间。
3. 未读数字位于头像右上角，`99+`、@ 提醒和免打扰图标互不遮挡。
4. 免打扰会话仍显示数字未读，静音图标位于右下。
5. 正常发送只显示气泡左侧转圈，最终成功后转圈消失。
6. 发送失败只显示气泡左侧红色失败按钮，不再同时转圈；点击可重试。
7. 上传中取消按钮与发送失败按钮使用同一状态槽位，不与头像或气泡重叠。
8. 撤回已落库消息时显示转圈，普通 outbox 消息不会被误判为撤回中。
