# IM 客户端头像与群聊发送者名称设计

## 目标

在会话列表、聊天页面和通讯录中补齐一致的身份识别信息。用户使用姓名首字符头像，群聊使用固定群组图标；群聊消息明确展示发送者姓名，使用户无需根据消息内容猜测发送者。

## 范围

本次只调整移动客户端展示和已有姓名数据的消费方式，不新增后端字段、不持久化头像、不接入图片上传，也不改变消息协议。

## 头像规则

- 用户头像显示姓名去除首尾空白后的第一个 Unicode 字符。
- 英文字母转换为大写；中文等其他字符保持原样。
- 姓名缺失时显示 `U`。
- 背景色根据用户 ID 从固定色板稳定选取，同一用户在不同页面保持一致。
- 当前账号使用登录态中的显示名称和用户 ID。
- 群聊统一显示固定的双人群组图标，不使用群名首字符。

## 页面设计

### 会话列表

- 每个会话项左侧增加头像。
- 单聊使用对方姓名首字符头像，优先使用会话的 `displayName`，其次使用 `peerName`，最后回退到 `用户 #ID`。
- 群聊使用固定群组图标。
- 未读数、消息预览、@ 提示和点击行为保持不变。

### 聊天页面

- 自己的消息头像显示在气泡右侧，对方消息头像显示在气泡左侧。
- 单聊双方只显示头像，不额外显示姓名。
- 群聊中的对方消息在气泡上方显示发送者姓名；自己的消息不重复显示自己的姓名。
- 群聊发送者姓名复用当前页面已加载的群成员和完整通讯录映射。
- 姓名查找顺序为群成员名称、通讯录名称、`用户 #ID`；发送者 ID 缺失时显示“未知用户”。
- 系统消息继续居中显示，不增加头像。

### 通讯录

- 用户行左侧增加姓名首字符头像。
- 部门行继续使用部门图标，用户头像和部门图标在视觉上保持可区分。
- 层级导航、部门全选、禁选逻辑和手工输入用户 ID 的能力保持不变。

## 组件边界

- `InitialAvatar` 只负责用户首字符、稳定颜色、尺寸和可访问性标签。
- `GroupAvatar` 只负责固定群组图标、尺寸和可访问性标签。
- 各页面负责决定展示哪个名称和用户 ID，不在头像组件内发起数据请求。
- 首字符与颜色计算集中在头像组件模块，避免会话列表、聊天页和通讯录重复实现。

## 数据流与失败回退

会话列表使用本地会话快照已有名称。聊天页面进入群聊时并行读取群资料、群成员和完整通讯录，然后合并姓名映射；任何一个远程请求失败时仍使用其余可用数据，不阻塞本地消息展示。通讯录沿用完整通讯录接口结果。

## 验证

按当前项目约定不新增或运行测试。实施完成后执行：

- 移动客户端 TypeScript 类型检查。
- SDK Core TypeScript 类型检查。
- 平台依赖边界扫描。
- Git 差异格式检查。
- 人工检查单聊、群聊、通讯录的头像方向和姓名回退。

## 非目标

- 真实图片头像、头像上传和图片缓存。
- 自定义群头像。
- 修改服务端消息结构或数据库表。
- 调整聊天气泡之外的消息交互。
