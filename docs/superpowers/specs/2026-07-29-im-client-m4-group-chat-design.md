# IM 客户端 M4 · 完整群聊管理设计

> 状态：已通过头脑风暴评审（2026-07-29）。
> 上游：`docs/superpowers/plans/2026-07-29-im-client-HANDOFF.md`。
> 后端契约：`docs/superpowers/specs/2026-07-23-im-mvp-phase3-group-chat-design.md`。

## 一、目标与范围

M4 在现有单聊、离线同步、多端登录和已读回执之上，一次接入完整群聊管理能力：

- 创建群聊并多选初始成员
- 在会话列表展示真实群名
- 收发群文本消息并离线同步
- 展示结构化群系统消息
- 查看群详情和成员列表
- 添加成员、移除成员、修改群名
- 设置或取消管理员、禁言或解除禁言
- 转让群主、退出群聊、解散群聊

本期不接入图片、语音、文件、链接卡片、撤回和 `@` 提及。这些能力继续作为独立里程碑，避免与群管理界面耦合。

## 二、架构决策

群业务统一放在 `im-sdk-core`，React Native 页面只负责交互和展示。

新增 `GroupService`，通过现有 `HttpPort` 调用 `/im/groups` REST 接口，向页面暴露类型明确的方法。它不依赖 React、React Native、Axios 或 SQLite 的具体实现，因此未来其他客户端也能复用。

现有 `ChatScreen` 同时承载单聊和群聊。消息发送、WebSocket 推送、SQLite 落库、离线补拉、失败重发和未读推进继续走现有通用链路；页面只针对会话类型调整标题、已读标签和系统消息样式。

移动端新增两个界面职责：

- `CreateGroupScreen`：填写群名、从现有联系人数据源多选成员并建群。
- `GroupDetailsScreen`：展示群资料和成员，并按当前用户角色提供管理操作。

联系人数据获取抽成可复用能力，现有新建单聊页保持单选，建群和群内加人使用多选。

## 三、核心类型与 SDK 接口

`im-sdk-core` 增加以下领域类型：

- `GroupRole = 'OWNER' | 'ADMIN' | 'MEMBER'`
- `GroupDetail`：`groupId`、`name`、`ownerId`、`memberCount`、`myRole`
- `GroupMember`：`userId`、`role`、`muted`
- `CreateGroupResult`：`groupId`、`cid`

`GroupService` 提供与后端接口一一对应的方法：

- `createGroup(name, memberIds)`
- `getGroup(groupId)` / `getMembers(groupId)`
- `addMembers(groupId, userIds)` / `removeMember(groupId, userId)`
- `renameGroup(groupId, name)`
- `setMemberRole(groupId, userId, role)`
- `setMemberMuted(groupId, userId, muted)`
- `transferOwner(groupId, newOwnerId)`
- `leaveGroup(groupId)` / `dissolveGroup(groupId)`

RN SDK 工厂返回 `groups` 服务实例，与现有 `auth`、`chat`、`sync` 并列。所有请求复用登录态、统一响应解包和既有错误处理。

## 四、本地会话快照与群名

SQLite 仍是会话列表的界面数据源。会话快照增加可持久化的展示名称字段，群会话保存真实群名，单聊继续保存对端名称。

全量同步会话列表时：

1. 先写入服务端返回的通用会话字段。
2. 对 `GROUP` 会话按 `groupId` 获取群详情。
3. 将群名合并写入本地快照。
4. 单个群详情失败时保留旧群名；本地无旧值时显示 `群聊 #groupId`，不阻断其他会话同步。

建群或改名成功后立即写入/刷新对应快照。旧响应不得覆盖更新的本地名称和同步位点。

退群或解散后，从本地删除该会话的消息、outbox 和会话快照，再返回会话列表并触发全量同步。删除只针对明确的 `cid`，不得影响其他账号或会话。

## 五、页面与导航

### 会话列表

- “新建”入口同时提供“发起单聊”和“创建群聊”。
- 群会话展示真实群名、最新消息摘要、未读数和同步状态。
- 进入群会话时向 `ChatScreen` 传入 `cid`、`groupId`、`conversationType` 和标题。

### 创建群聊

- 群名必填，前端做去空格和长度校验，后端继续作为最终校验边界。
- 联系人列表支持多选；当前用户不出现在候选成员中。
- 至少选择一位其他成员后才允许提交。
- 提交期间禁用按钮，成功后同步新会话并直接进入群聊。

### 群聊页面

- 沿用现有文本消息列表、输入框、发送状态和失败重发。
- 群聊不显示单聊的“对方已读”标签。
- 标题栏右侧提供群详情入口。
- `SYSTEM` 消息根据 `event`、`operatorId`、`targetIds` 和 `extra` 渲染为居中的灰色提示，不显示普通气泡和头像。
- 对未知系统事件使用安全兜底文案，避免结构升级导致页面崩溃。

### 群详情与成员管理

- 页面加载群详情和成员列表，并支持手动刷新。
- 所有用户可查看成员；OWNER/ADMIN 可看到管理入口。
- OWNER 可改名、加人、踢非群主成员、设置管理员、禁言普通成员、转让群主和解散。
- ADMIN 可改名、加人、踢普通成员和禁言普通成员。
- MEMBER 只能查看成员并退出群聊。
- 客户端按钮可见性用于改善体验，后端角色校验始终是最终权限边界。
- 成员级操作只锁定对应成员；群级提交锁定对应按钮，防止重复请求。

危险操作使用二次确认：转让群主、退出群聊和解散群聊必须明确展示后果。

## 六、数据流

### 建群

1. 用户填写群名并多选联系人。
2. `GroupService.createGroup` 调用后端。
3. 客户端用返回的 `groupId/cid` 拉取群详情并同步会话。
4. 导航进入群聊；同步失败时保留建群结果并允许用户在会话列表重试。

### 群消息

1. 文本发送继续调用现有 `ChatService.sendText`。
2. ACK、最终 PUSH、超时和重试保持单聊语义。
3. WebSocket PUSH 与 REST 补拉统一经 `SyncEngine` 落库。
4. `SYSTEM` 类型原样持久化，由 UI 在读取时格式化。

### 群管理

1. 页面调用单一群管理接口。
2. 成功后重新加载群详情和成员列表。
3. 会影响会话标题或成员资格的操作额外触发对应会话同步。
4. 收到相关 SYSTEM PUSH 时，当前群详情页执行合并刷新，其他页面只刷新会话和消息。

## 七、错误处理与一致性

- 网络失败不清空已有群详情、成员或会话快照，并提供重试入口。
- 400 级业务错误展示后端可读信息；403 明确提示权限或成员状态已变化；401 沿用现有登录失效流程。
- 被禁言或已不在群时，服务端 `ERROR` 帧继续使对应 outbox 消息进入失败状态，页面显示可理解原因。
- 页面上的角色判断可能因其他设备操作而过期；任何后端拒绝都以服务端结果为准，并立即刷新群详情。
- 群名、会话位点和已读位点只允许前向或按服务端权威结果更新，旧并发响应不得覆盖新状态。
- 退出或解散成功后的本地清理必须幂等，重复执行不会报错。

## 八、验证策略

按当前交接约定，本期不新增或代跑自动化测试。实现完成后只运行：

- `im-sdk-core` TypeScript 类型检查
- `app-mobile` TypeScript 类型检查
- `git diff --check`
- core 平台依赖边界检查

最终提供双模拟器手工验收清单，至少覆盖：

- 建群、真实群名、群文本收发和离线补拉
- SYSTEM 消息展示和未知事件兜底
- OWNER、ADMIN、MEMBER 三种角色下的按钮与服务端权限
- 加人、踢人、改名、设管理员、禁言、转让群主
- 退群和解散后的本地清理与导航
- 断网、重复点击、权限过期和业务失败提示
- 单聊发送、已读回执、离线同步和账号隔离不回归

## 九、完成标准

M4 完成时，用户可仅通过移动端创建和完整管理群聊；群文本消息在线与离线链路可用；群名称、成员和权限状态在重连后保持一致；所有破坏性群操作有二次确认；现有单聊链路不因群聊接入而改变语义。
