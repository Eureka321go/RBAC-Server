# IM 客户端语音消息设计

> 状态：用户已逐段确认方案（2026-07-29）。本期同时修改后端媒体校验、SDK Core、React Native 适配层和移动端应用。

## 目标与范围

本期打通语音消息的完整闭环：用户在聊天页按住录音、上滑取消、松开发送；发送方与接收方均显示由真实录音振幅生成的波形；点击语音气泡可播放、暂停和继续；同一时间只播放一条语音；接收方完整听完后消除本机未听标记。

首期同时支持 Android 与 iOS。单条语音最短 1 秒、最长 60 秒，统一录制为单声道 AAC-LC `.m4a` 文件并以 `audio/mp4` 上传。语音文件继续直传 MinIO/S3，复用图片和文件已经具备的上传、断点恢复、失败重试、撤回、临时下载地址刷新和本地下载缓存能力。

首期不做语音转文字、倍速、拖动定位、自动连播、听筒切换、跨设备已听同步、向发送方回传已听状态、锁定录音、后台录音或实时音视频通话。

## 依赖选择

React Native 原生音频采用 `react-native-nitro-sound`。它同时覆盖录音、录音计量、播放和进度回调，适合在一次录音中采集真实振幅；依赖只出现在 `@im/sdk-rn`，SDK Core 与移动端页面不直接导入第三方音频包。麦克风授权状态与跳转系统设置由 `react-native-permissions` 统一适配，避免页面分别维护 Android 与 iOS 权限分支。

没有选择 `react-native-audio-api`，因为本期不需要完整 Web Audio 图、PCM 管线或复杂音频处理；没有自建 Kotlin/Swift 音频桥，因为两端长期维护成本与本期收益不匹配。

## 总体架构

能力拆成四个边界清晰的部分：

1. 后端沿用现有 AUDIO 媒体上传与消息存储链路，只补充语音元数据校验。
2. SDK Core 定义平台无关的录音与播放端口，扩展媒体上传任务以持久化语音时长和波形，并负责已听状态的 SQLite 存取。
3. React Native 适配层用 `react-native-nitro-sound` 实现麦克风录制、分贝采样、音频焦点和播放进度；平台权限声明分别放入 Android Manifest 与 iOS Info.plist。
4. 移动端应用负责按住/上滑手势、录音浮层、语音气泡以及全局单实例播放协调。

录音、播放和 UI 通过端口与事件通信。`ChatScreen` 只组合组件和绑定会话数据，手势状态机、波形处理和播放器生命周期放入独立模块，避免继续扩大页面职责。

## AUDIO 消息模型

发送消息体为：

```json
{
  "objectKey": "im/c_1_2/202607/uuid.m4a",
  "filename": "voice-1722240000000.m4a",
  "mime": "audio/mp4",
  "size": 48213,
  "duration": 8,
  "waveform": [12, 18, 31, 44, 27, 63, 71, 52, 36, 20, 15, 24, 48, 80, 66, 41, 25, 18, 33, 57, 72, 68, 49, 29, 17, 22, 39, 61, 75, 54, 35, 21, 16, 28, 46, 69, 82, 59, 38, 23, 19, 32, 51, 73, 64, 43, 26, 14]
}
```

- `duration` 是向上取整后的整秒，范围 1～60。
- `waveform` 固定为 48 个整数，每个值范围 0～100。
- `objectKey`、`size` 和 `mime` 继续由现有媒体安全校验与对象存储 HEAD 结果约束。
- `localUri`、实时振幅样本、上传进度和播放位置只存在于本地状态，不进入发送帧或 MongoDB。

后端在 AUDIO 发送校验中检查 `duration` 与 `waveform` 的类型、长度和数值范围。客户端解析下行消息时也执行防御性校验；旧消息缺少波形或字段损坏时仍允许播放，并使用均匀占位波形降级，不让异常消息破坏聊天页渲染。

## 振幅采集与波形生成

录音时启用原生 metering，约每 100ms 接收一次分贝值。客户端先将有效分贝夹在 `-60dB～0dB`，再转换为 `0～1` 的线性强度，供录音浮层实时显示。

录音结束后按时间把全部有效样本划分为 48 个连续区间，每个区间取峰值以保留短促发声，再应用轻量平滑避免单点尖峰。最终量化为 `0～100` 的整数数组。样本不足 48 个时采用时间插值补齐；完全没有有效 metering 数据时取消发送并提示录音失败，不能伪造一条看似有效的静音波形。

归一化采用固定分贝边界，不按每条音频自己的最大值二次拉伸。这样安静录音仍然显示较低振幅，不会被错误渲染成与正常说话同样饱满的波形。

## 录音交互与状态机

聊天输入栏增加键盘/语音切换按钮。切到语音模式时保留文字草稿并显示“按住说话”；切回键盘后恢复原草稿。首次切换到语音模式时请求麦克风权限，避免用户按住期间被系统权限弹窗打断。

录音状态为：

`idle -> starting -> recording -> cancelling | finishing -> enqueued -> idle`

失败或系统中断进入 `failed`，清理临时文件后回到 `idle`。任何一次手势只允许执行一次停止或取消，防止 60 秒自动结束与随后松手产生重复语音。

交互规则：

1. 按下“按住说话”后立即开始录音并显示居中浮层。
2. 浮层实时显示时长和随当前振幅变化的波形。
3. 手指向上移动超过约 80px 时进入红色“松开取消”状态；移回阈值内恢复发送状态。
4. 在取消状态松手会停止录音并删除临时文件。
5. 正常松手时，不足 1 秒则删除并提示“说话时间太短”；1～60 秒则生成最终波形并立即进入媒体上传队列。
6. 到达 60 秒时自动结束并发送，忽略之后到达的松手结束动作。
7. 页面离开、应用进入后台、权限被撤销、原生录音被系统打断或组件卸载时取消本次录音并清理临时文件，不发送残缺语音。

开始录音前先停止当前播放，避免扬声器声音被重新录入。录音时禁止再次切换附件、发送文字或启动第二次录音。

## 权限与录音格式

Android 声明 `RECORD_AUDIO` 并在运行时请求；iOS 声明 `NSMicrophoneUsageDescription` 并使用系统麦克风授权。普通拒绝显示中文说明并允许下次重试；永久拒绝或“不再询问”时提供前往系统设置的入口。用户从设置恢复权限后，返回前台重新检查权限状态。

两端统一目标格式为 AAC-LC、16 kHz、32 kbps、单声道、`.m4a`、`audio/mp4`。若某平台录音器不能严格产出目标 MIME，适配层在入队前以实际容器和 MIME 为准，但只能落在服务端 AUDIO 白名单内；不做客户端转码。

## 上传、恢复与结算

SDK Core 的媒体类型扩展为 `IMAGE | AUDIO | FILE`。语音录音完成后将临时文件、`duration` 和最终 `waveform` 交给现有 `MediaUploadService`：

1. 先把原生临时录音复制到应用持久目录。
2. 在 `media_upload_task.metadata_json` 中持久化经过校验的 `duration` 与 `waveform`，避免为每种媒体持续增加稀疏列。
3. 小于 5 MiB 走单次预签名 PUT，达到阈值时沿用 Multipart；服务端仍执行 AUDIO 的 20 MiB 上限和 MIME 白名单校验。
4. 上传期间聊天页显示本地波形、时长、进度和取消入口。
5. 上传完成后使用同一 `clientMsgId` 进入 outbox ACK/PUSH 链路，发送帧移除本地路径和上传状态。
6. 应用重启或网络恢复后，账号匹配且本地文件存在的任务可继续上传，波形和时长不丢失。
7. 最终 PUSH 落库后删除上传任务和发送端持久副本；失败可重试，取消则删除任务与文件。

语音撤回继续走现有两分钟撤回链路。若正在播放的语音被撤回，立即停止播放、释放音频焦点并把气泡替换为撤回占位。

## 播放与下载

应用维护一个全局播放协调器，任意时刻最多只有一条活动语音。气泡交互为：

- 点击未播放语音：停止并归零上一条，优先使用本地发送副本或下载缓存；没有缓存时刷新预签名地址并下载，然后播放。
- 点击正在播放的语音：暂停。
- 再次点击同一气泡：从暂停位置继续。
- 点击另一条语音：当前语音停止并归零，新语音开始。
- 播放完成：位置归零并发出完成事件。

播放进度按 `currentPosition / duration` 映射到 48 个振幅柱。已播放部分使用主色，未播放部分使用弱色；暂停时保留进度，停止或完成时归零。下载期间气泡显示轻量加载状态，失败时显示中文提示，再次点击重新尝试。

播放器统一处理音频焦点。耳机或蓝牙设备断开、电话/系统音频打断、应用进入后台、账号退出、页面数据被清理或消息撤回时暂停并释放焦点，不自动恢复，避免突然外放。

## 本地未听状态

接收方尚未完整播放的语音显示未听圆点。只有播放器正常到达完成事件才写入已听状态；开始播放、暂停、失败或手动切换到另一条都不算已听。自己发送的语音不显示未听标记。

SQLite 新增本地语音已听记录，以 `accountId + cid + seq` 唯一标识并记录 `heardAt`。状态不上传服务器，不影响现有会话未读数，也不向发送方回传。账号切换严格隔离；清理对应消息或账号本地数据时同步清理孤立记录。

## 组件边界

- `VoiceComposerControl`：键盘/语音切换和按住手势入口。
- `VoiceRecordingOverlay`：录音时长、实时波形、取消状态和无障碍提示。
- `VoiceMessageContent`：波形、时长、未听标记、下载与播放状态展示。
- `voiceWaveform`：分贝夹取、强度转换、48 点重采样和下行字段校验，保持为纯函数。
- `VoicePlaybackCoordinator`：全局单实例播放状态、活动消息切换和生命周期清理。
- SDK Core 录音/播放端口：描述开始、停止、取消、计量、播放、暂停、停止和进度事件，不暴露 Nitro Sound 类型。
- SDK RN 音频适配器：唯一直接使用 `react-native-nitro-sound` 的模块。

## 错误、安全与清理

- 麦克风拒绝、永久拒绝、录音启动失败、系统中断、无有效振幅、文件丢失、上传失败、下载失败和解码失败均映射为稳定错误原因与中文提示。
- 所有异步录音停止、上传、下载和播放回调都校验当前操作令牌，过期回调不能覆盖新操作状态。
- 后端不信任客户端 `duration`、`waveform`、`size` 或 `mime`；对象元数据继续以存储 HEAD 为准，语音展示元数据执行严格边界校验。
- 开始录音、切换账号、退出登录、进入后台和组件卸载都会释放录音器、播放器、监听器与音频焦点。
- 取消、过短录音、录音失败和发送成功都会删除不再需要的临时或持久本地文件；可重新下载的接收文件留在现有媒体缓存中。
- 播放和录音互斥，避免音频焦点竞争与回声录入。

## 验证标准

遵循当前项目约定，本期不新增或代跑自动化测试。实现后执行与改动范围相符的 TypeScript 类型检查、Android/iOS 原生配置检查、相关 Maven 跳过测试构建和 `git diff --check`，并把手动验收步骤交给用户执行。

手测至少覆盖：

1. Android 与 iOS 首次授权、普通拒绝、永久拒绝及从设置恢复。
2. 按住录音、上滑取消、移回恢复、松开发送和快速点击不足 1 秒。
3. 60 秒自动结束只发送一次，松手不产生第二条。
4. 实时波形随音量变化；安静与大声录音生成明显不同的持久波形。
5. 单聊、群聊、双端实时接收与接收方离线后同步。
6. 上传进度、断网重试、应用重启后恢复、取消和源文件丢失。
7. 播放、暂停、继续、完成归零和点击另一条时切换。
8. 下载缓存复用、临时 URL 过期刷新、下载/解码失败后重试。
9. 未听圆点只在完整播放后消失，账号切换后状态不串号。
10. 播放中开始录音、进入后台、耳机断开、系统打断和消息撤回。
11. 发送后两分钟内撤回，双端均停止可能正在进行的播放并显示撤回占位。
12. 文字草稿在键盘/语音模式切换后保持不变。
