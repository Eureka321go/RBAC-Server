# 工作流审批前端设计

## 目标

基于现有 Vue 3、Element Plus、动态菜单和权限体系，实现 `docs/06-工作流审批设计.md` 中规划的工作流前端，并补齐普通用户发起流程和选择转办人所需的最小后端查询能力。

首期覆盖流程定义管理、发起审批、我的待办、我的已办、我发起的、抄送我的、实例详情和顶栏待办角标。流程设计使用表单式节点配置，不引入拖拽设计器；业务表单使用通用键值编辑器，不实现请假等特定业务表。

## 架构与文件边界

工作流代码按定义、任务和实例三个功能切片组织：

- `frontend/src/api/workflow/`：接口类型及请求函数，按 `definition.ts`、`task.ts`、`instance.ts` 拆分。
- `frontend/src/views/workflow/definition/DefinitionView.vue`：定义列表及定义/节点编辑。
- `frontend/src/views/workflow/task/TodoView.vue`：待办查询和审批动作。
- `frontend/src/views/workflow/task/DoneView.vue`：已办查询。
- `frontend/src/views/workflow/instance/MineView.vue`：发起、查询及撤回。
- `frontend/src/views/workflow/instance/CcView.vue`：抄送查询和已读处理。
- `frontend/src/views/workflow/instance/DetailDrawer.vue`：跨页面复用的实例详情抽屉。
- `frontend/src/components/workflow/`：状态标签、通用表单编辑器等小型复用组件；仅在实际出现重复时提取。
- `frontend/src/stores/workflow.ts`：只维护全局待办数量及轮询生命周期，不集中存放页面分页数据。

页面自己的查询、分页、弹窗和提交状态保留在页面组件内，避免为普通 CRUD 引入过度的全局状态。

## 后端最小补充

新增仅登录态可访问的工作流选项接口：

- `GET /workflow/definition/options`：返回所有已启用流程的 `processKey`、`name`、`category`、`formKey` 和 `version`，供普通用户发起审批。
- `GET /workflow/assignee/users`：按用户名或昵称检索启用用户，返回有限的 `id`、`username`、`nickname`、`deptName` 字段，供转办和定义中的指定用户选择使用。

角色和岗位选择继续复用现有 options 接口。流程定义管理者在当前种子角色下同时拥有系统角色、岗位和用户查询权限；用户检索使用新的工作流专用接口，避免普通审批用户必须获得系统用户管理权限。接口仍由后端校验登录态，不在前端信任用户输入。

## 页面与交互

### 流程定义

列表支持按流程标识、名称、分类和状态筛选，提供新增、编辑、启停、删除和详情操作，并沿用现有 `v-permission` 按钮权限。

新增/编辑使用宽对话框或抽屉。基础信息包括流程标识、名称、分类、表单标识、状态和备注。节点以可增删、上移、下移的卡片列表呈现，每个节点配置名称、审批人来源、审批人值、审批模式、驳回策略和可选条件表达式。保存前根据当前顺序重新生成从 1 开始的 `nodeOrder`。

`USER`、`ROLE`、`POST` 使用多选框并将 ID 序列化为逗号分隔字符串；`DEPT_LEADER`、`INITIATOR_SELF`、`INITIATOR_LEADER` 不显示取值选择器。节点至少保留一个，指定用户、角色或岗位时必须选择至少一项。

### 发起与我发起的

“发起审批”从已启用流程选项中选择流程，填写标题和可选业务单号，并通过可增删行编辑器录入表单快照。每行包含字段名、类型和字段值；类型支持文本、数字、布尔值。提交时将各行转换为 `Record<string, unknown>`，拒绝空字段名、重复字段名和无效数字。

“我发起的”支持标题、流程标识和实例状态筛选。每行可打开详情；状态为 `RUNNING` 时显示撤回，撤回前确认并允许填写不超过 500 字的意见。

### 待办与已办

待办按标题查询，列表展示标题、流程标识、发起人、当前节点和创建时间。打开审批抽屉时并行加载实例详情。用户可以填写不超过 500 字的意见并同意、驳回或转办；转办必须选择启用用户。动作提交期间禁用按钮，成功后关闭抽屉并刷新列表和全局待办数量。

已办列表展示处理状态和处理时间，仅提供详情查看。

### 抄送与详情

抄送列表展示标题、流程标识、发起人、实例状态、抄送时间和未读状态。打开未读项时调用已读接口并局部更新列表。

通用详情抽屉展示实例概要、表单快照、节点任务状态和审批记录时间线。未知表单对象使用键值表展示，复杂值使用格式化 JSON 展示。所有枚举均保留原始值作为未知值兜底，避免后端新增状态导致空白。

### 待办角标

顶栏增加可点击的待办图标，角标显示待办总数，点击跳转 `/approval/todo`。登录后的基础布局挂载时立即查询一次，之后每 30 秒刷新；页面隐藏时不轮询，恢复可见后立即刷新。组件卸载时清理定时器。查询失败沿用全局错误提示，并保留上一次成功数量。

## 数据流与错误处理

所有请求继续通过现有 `request.ts`，复用 Token 刷新、国际化请求头和统一错误消息。页面使用 `try/finally` 保证 loading 状态恢复；破坏性操作使用确认框；提交成功后显示本地化成功消息并刷新相关数据。

分页查询变更时回到第一页。详情请求失败时不打开空抽屉。审批动作失败时保留用户输入，便于修正或重试。前端做必填、格式和长度校验，后端继续作为最终授权及数据校验边界。

## 国际化与可访问性

新增的标题、字段、状态、操作、校验和反馈同时写入 `zh-CN.ts` 与 `en-US.ts`。表单控件均有可见标签；纯图标顶栏操作提供 title；状态不只依赖颜色，同时显示文字；键盘可完成搜索、填写、提交和关闭操作。

## 测试与验收

前端引入与 Vite 兼容的 Vitest 测试配置，优先测试独立逻辑：

- 通用表单行转换为 `formData`，覆盖文本、数字、布尔、重复键和无效数字。
- 工作流枚举的标签及标签颜色映射，覆盖未知值兜底。
- 工作流 API 的请求路径、HTTP 方法和参数结构。

组件关键流程通过最小集成测试覆盖：定义节点顺序生成、待办动作触发刷新、未读抄送打开后标记已读。若现有测试基础不足以可靠运行完整浏览器测试，本阶段以单元/组件测试、类型检查、lint 和生产构建作为验收门槛，并保留手工联调清单。

最终验收命令包括测试、`npm run type-check`、`npm run lint` 和 `npm run build`。同时核对动态路由组件路径与种子菜单完全匹配。

## 非目标

- BPMN 或拖拽式流程设计器。
- 特定请假、报销、采购业务表单。
- WebSocket、站内消息或外部通知。
- 加签和管理员强制终止；当前后端未提供对应接口。
- 修改运行中实例或实现复杂条件表达式编辑器。
