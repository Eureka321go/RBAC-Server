# IM 客户端 @ 提及设计

## 目标与范围

本期为移动端群聊补齐 `@成员` 与 `@所有人` 的输入、发送、展示和提醒闭环。服务端已有提及对象校验、`mention_seq` 推进和会话列表 `hasMention` 字段，客户端在现有能力上完成交互接入。

本期支持：

- 在群聊输入 `@` 后打开成员选择面板
- 按成员显示名搜索
- 多选成员、自动去重
- 群主和管理员选择“所有人”
- 输入框以普通文本展示并维护结构化绑定，消息气泡突出显示提及片段
- 发送、失败重发、实时接收和离线同步保留提及语义
- 被提及方显示现有 `[有人@我]` 强提醒，读后自动消除

本期不做：单聊提及、跨页面草稿持久化、提及通知声音或系统推送差异化。

## 方案选择

采用结构化提及片段模型。输入框显示普通文本，同时维护每个提及片段的用户 ID、显示名和文本范围。相比发送时按名称反向查找，该方案能正确区分重名成员；相比独立标签输入，它更符合常见即时通信输入习惯。

## 组件与职责

### 聊天页面

`ChatScreen` 负责：

- 保存当前文本、光标选择区和提及片段
- 识别群聊中输入的 `@` 触发字符
- 控制成员选择面板
- 将结构化草稿交给 SDK Core 发送
- 根据消息中的安全范围渲染提及强调样式

单聊继续使用现有纯文本发送流程，不打开成员选择面板，也不携带提及字段。

### 成员选择面板

新增独立的群成员提及选择面板，接收群成员、当前用户角色和已选用户 ID，输出本次确认的成员集合或“所有人”。面板具备：

- 显示名包含搜索，忽略搜索词首尾空格
- 多选和已选状态
- 同一成员只能选择一次
- 不展示当前用户
- 仅向 `OWNER`、`ADMIN` 展示“所有人”
- “所有人”与普通成员选择互斥

空搜索展示全部可选成员。群成员尚未加载或加载失败时不打开面板，并显示中文错误提示。

### 提及草稿模型

每个普通成员提及片段包含：

```ts
interface MentionDraftRange {
  userId: number;
  displayName: string;
  start: number;
  end: number;
}
```

`start` 为包含 `@` 的起始位置，`end` 为提及文字后的排他位置，索引采用 JavaScript UTF-16 字符串下标，与 React Native `TextInput` 的选择区保持一致。`@所有人`使用独立的 `mentionAll` 状态，并维护对应的显示范围。

提及草稿逻辑放入独立模块，负责插入、去重、范围调整、冲突失效和发送 body 构建，避免聊天页面承担字符串算法。

## 输入交互

1. 用户在群聊输入框键入 `@`，客户端记录触发字符范围和当前光标位置，打开成员选择面板。
2. 用户在面板内搜索并勾选一个或多个成员，然后确认。
3. 客户端用 `@显示名 ` 替换触发字符；多人按选择顺序连续插入。
4. 再次选择已经存在于有效提及片段中的用户时不重复插入。
5. 选择“所有人”时清除本次面板里的普通成员选择并插入 `@所有人 `；已有的普通成员片段保留为普通文本但移除提及绑定，避免同时发送 `mentionAll` 与 `mentions`。
6. 在提及片段前后插入或删除文本时，后续范围按长度差调整。
7. 编辑操作与某个提及片段相交时：完整删除则移除片段；部分修改则将该片段降级为普通文本并移除绑定，防止文字和用户 ID 错配。
8. 发送成功发起后清空文本、光标和提及片段；发送调用同步失败时沿用 outbox 失败消息，不恢复输入框草稿。

关闭成员面板但不确认时，仅保留用户已经输入的 `@`，不改变草稿。

## 协议与数据流

SDK Core 的 `sendText` 增加可选提及参数，在服务边界统一过滤非正整数、去重，并确保 `mentionAll` 与 `mentions` 不同时发送。

普通成员提及示例：

```json
{
  "text": "@张三 @李四 请确认",
  "mentions": [10, 11],
  "mentionRanges": [
    {"userId": 10, "start": 0, "end": 3},
    {"userId": 11, "start": 4, "end": 7}
  ]
}
```

`@所有人`示例：

```json
{
  "text": "@所有人 请确认",
  "mentionAll": true,
  "mentionRanges": [
    {"mentionAll": true, "start": 0, "end": 4}
  ]
}
```

服务端现有逻辑消费 `mentions` 和 `mentionAll`，并原样保存、扇出整个 body。新增的可选 `mentionRanges` 仅供客户端准确展示，旧客户端会自然忽略。

发送链路保持不变：结构化 body 先写入 outbox，随后通过 `SEND` 发出；失败重发直接复用 outbox 原始 body，不重新解析显示名。实时 `PUSH` 和 REST 离线同步都通过现有 SyncEngine 原样落库。

## 展示与安全降级

渲染消息时先校验 `mentionRanges`：

- `start/end` 必须是安全整数并位于文本范围内
- `start < end`
- 范围按起点严格递增且不能重叠
- 普通成员范围的 `userId` 必须存在于 body 的 `mentions` 中
- `mentionAll` 范围只在 body 的 `mentionAll === true` 时有效
- 对应文本必须以 `@` 开头

全部校验通过后将文本切成普通片段和提及片段，并用强调色渲染。任一范围无效时，整条消息安全降级为普通文本，避免部分错误元数据造成错位或崩溃。没有 `mentionRanges` 的历史消息也按普通文本展示。

## 错误处理

- `MENTION_NOT_MEMBER`：显示“提及的成员已不在群聊中”
- `MENTION_ALL_FORBIDDEN`：显示“只有群主或管理员可以@所有人”
- 群成员加载失败：显示“群成员加载失败，请稍后重试”
- 其他发送错误：沿用现有发送失败状态和重发入口

客户端隐藏越权入口只是交互优化，权限仍以服务端判断为准。成员在选择后退出群聊、客户端角色缓存过期等竞争情况由服务端拒绝。

## 会话提醒

服务端在提及消息定序后推进被命中成员的 `mention_seq`。客户端会话快照已有 `mentionSeq` 和 `hasMention`，会话列表继续显示 `[有人@我]`。用户进入会话后，现有已读上报推进 `last_read_seq`；下一次快照同步后 `mentionSeq <= lastReadSeq`，提醒自动消除。

提及不改变消息扇出范围，也不单独修改普通未读数。

## 验证方式

按用户约定，不新增或代跑自动化测试。实现完成后仅执行 TypeScript 类型检查、相关编译检查和 `git diff --check`，由用户手动验证视觉与交互。

手测覆盖：

1. 单个成员提及并正常收发
2. 多成员提及、重复选择去重
3. 名称搜索与空搜索列表
4. 删除完整提及片段、修改片段内部文字
5. 群内重名成员分别选择和正确提醒
6. 群主、管理员发送 `@所有人`
7. 普通成员看不到“所有人”，服务端越权错误显示中文
8. 成员退出后发送得到中文错误，失败消息可重发
9. 被提及方会话列表显示 `[有人@我]`，进入并同步后消除
10. 双设备实时接收与离线恢复后展示一致
11. 单聊输入 `@` 不打开成员面板
