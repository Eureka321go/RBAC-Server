# RBAC 系统 —— 国际化（i18n）设计文档

> 记录时间：2026-07-08
> 当前基础：前端 Vue 3.5 + TS + Vite + Pinia + Element Plus 2.14 + Tailwind 4；后端 Spring Boot 3.4.1
> 本阶段目标：为前后端引入统一的多语言能力，首期支持简体中文（`zh-CN`）与英文（`en-US`），可扩展

---

## 一、设计目标

- **前端 UI 文案**、**Element Plus 内置组件文案**、**后端提示/校验/异常消息**统一多语言。
- 语言选择**持久化**，并可绑定到用户偏好（登录后跟随账号）。
- **可扩展**：新增语种只需追加语言包与后端资源文件，不改代码结构。
- **默认 `zh-CN`**，与项目"面向用户输出用简体中文"的全局偏好一致。

**首期语种**：`zh-CN`（简体中文，默认）、`en-US`（英文）。

---

## 二、整体方案

| 层次 | 方案 |
|------|------|
| 前端应用文案 | `vue-i18n` v11（Composition API 模式） |
| Element Plus | `el-config-provider` + 官方 locale 包动态切换 |
| 日期/时间 | `dayjs` + locale，或 `Intl.DateTimeFormat` |
| 数字/货币 | `Intl.NumberFormat` |
| 语言传递 | 请求头 `Accept-Language: zh-CN` |
| 后端消息 | Spring `MessageSource` + `messages_*.properties` |
| 语言持久化 | `localStorage` + 用户偏好落库（`sys_user.locale`） |

---

## 三、前端设计

### 1. 依赖与目录

新增依赖：`vue-i18n`。目录结构：

```
frontend/src
├── locales
│   ├── index.ts          # 创建 i18n 实例、语言列表、切换与持久化
│   ├── zh-CN/            # 按模块拆分：common / menu / user / role ...
│   │   ├── common.ts
│   │   ├── system.ts
│   │   └── index.ts      # 聚合导出
│   └── en-US/
│       └── ...
└── stores
    └── locale.ts         # Pinia：当前语言、切换动作
```

### 2. i18n 实例

```ts
// locales/index.ts
import { createI18n } from 'vue-i18n'
import zhCN from './zh-CN'
import enUS from './en-US'

export const SUPPORT_LOCALES = [
  { value: 'zh-CN', label: '简体中文' },
  { value: 'en-US', label: 'English' },
] as const

export type LocaleKey = typeof SUPPORT_LOCALES[number]['value']
const STORAGE_KEY = 'app-locale'

export function getInitialLocale(): LocaleKey {
  const saved = localStorage.getItem(STORAGE_KEY) as LocaleKey | null
  if (saved) return saved
  const nav = navigator.language
  return nav.startsWith('zh') ? 'zh-CN' : 'en-US'
}

export const i18n = createI18n({
  legacy: false,               // Composition API
  locale: getInitialLocale(),
  fallbackLocale: 'zh-CN',
  messages: { 'zh-CN': zhCN, 'en-US': enUS },
})
```

`main.ts` 中 `app.use(i18n)`。组件内 `const { t } = useI18n()`，模板 `{{ t('user.username') }}`。

### 3. 语言包组织约定

- 按**模块**拆分文件，键名用**点分层级**：`user.username`、`common.button.save`、`role.dataScope.ALL`。
- 公共文案（按钮、状态、分页、校验提示）集中在 `common`，避免重复。
- 键名保持稳定，**禁止用中文原文当 key**（便于英文包对齐与检索）。

示例（`common.ts`）：

```ts
export default {
  button: { save: '保存', cancel: '取消', confirm: '确认', delete: '删除' },
  status: { ENABLED: '启用', DISABLED: '禁用' },
  pagination: { total: '共 {total} 条' },
}
```

### 4. Element Plus 联动

`App.vue` 根部包一层 `el-config-provider`，locale 随语言 store 变化：

```vue
<script setup lang="ts">
import { computed } from 'vue'
import { ElConfigProvider } from 'element-plus'
import zhCn from 'element-plus/es/locale/lang/zh-cn'
import en from 'element-plus/es/locale/lang/en'
import { useLocaleStore } from '@/stores/locale'

const localeStore = useLocaleStore()
const elLocale = computed(() => (localeStore.current === 'zh-CN' ? zhCn : en))
</script>

<template>
  <el-config-provider :locale="elLocale">
    <router-view />
  </el-config-provider>
</template>
```

### 5. Pinia 语言 store

```ts
// stores/locale.ts —— 统一切换入口
export const useLocaleStore = defineStore('locale', () => {
  const current = ref<LocaleKey>(getInitialLocale())
  function setLocale(l: LocaleKey) {
    current.value = l
    i18n.global.locale.value = l
    localStorage.setItem('app-locale', l)
    document.documentElement.lang = l
    // 登录态下同步到后端用户偏好（可选）
  }
  return { current, setLocale }
})
```

顶栏放语言下拉（`el-dropdown`）调用 `setLocale`。

### 6. 动态菜单标题国际化

后端菜单返回的 `title` 目前是中文字符串。两种策略：

- **策略 A（推荐，改动小）**：菜单表新增 `i18n_key` 字段（如 `menu.system.user`），前端渲染时若命中语言包用 `t(i18nKey)`，否则回退 `title`。
- **策略 B**：后端根据 `Accept-Language` 直接返回对应语言 `title`（依赖后端菜单多语言表，成本较高）。

首期采用策略 A：菜单 `title` 作为兜底，`i18nKey` 命中则覆盖。

### 7. axios 语言头

请求拦截器统一注入当前语言，供后端返回对应语言消息：

```ts
config.headers['Accept-Language'] = useLocaleStore().current
```

## 四、后端设计

### 1. MessageSource 配置

```java
@Bean
public MessageSource messageSource() {
    ReloadableResourceBundleMessageSource ms = new ReloadableResourceBundleMessageSource();
    ms.setBasename("classpath:i18n/messages");
    ms.setDefaultEncoding("UTF-8");
    ms.setDefaultLocale(Locale.SIMPLIFIED_CHINESE);
    return ms;
}

@Bean
public LocaleResolver localeResolver() {
    AcceptHeaderLocaleResolver r = new AcceptHeaderLocaleResolver();
    r.setDefaultLocale(Locale.SIMPLIFIED_CHINESE);
    r.setSupportedLocales(List.of(Locale.SIMPLIFIED_CHINESE, Locale.US));
    return r;
}
```

资源文件：`src/main/resources/i18n/messages_zh_CN.properties`、`messages_en_US.properties`。

```properties
# messages_zh_CN.properties
user.not.found=用户不存在
auth.password.error=账号或密码错误
common.success=操作成功

# messages_en_US.properties
user.not.found=User not found
auth.password.error=Incorrect account or password
common.success=Success
```

### 2. 统一响应消息国际化

- `Result<T>` 的 `message` 由 `code` 映射到消息 key，经 `MessageSource.getMessage(key, args, LocaleContextHolder.getLocale())` 解析。
- `BusinessException` 携带**消息 key + 参数**而非硬编码中文，`GlobalExceptionHandler` 统一翻译后返回。

```java
throw new BusinessException("user.not.found");
throw new BusinessException("common.max.length", new Object[]{ 50 });
```

### 3. 校验消息国际化

Bean Validation 消息走 `ValidationMessages_*.properties`，或将 `@NotBlank(message="{user.username.required}")` 交给 `MessageSource`（`LocalValidatorFactoryBean.setValidationMessageSource`）。

### 4. 数据字典多语言（可选，后置）

若字典项也需多语言，`sys_dict_data` 增加 `label_en` 等列，或建 `sys_dict_i18n` 关联表。首期字典维持单语言，界面文案靠前端语言包解决。

## 五、API 契约补充

- 客户端每次请求携带 `Accept-Language`；缺省视为 `zh-CN`。
- 后端所有面向用户的 `message` 均可被翻译；**枚举值、权限码、字段名等契约标识不翻译**（保持 camelCase 固定字符串，符合现有 API 契约）。
- 用户偏好语言：登录后 `GET /api/auth/me` 返回 `locale`，前端据此覆盖本地设置；`PUT /api/user/profile/locale` 保存偏好。

## 六、实施顺序

1. **前端基建**：装 `vue-i18n`，建 `locales/` 与 `stores/locale.ts`，`main.ts` 挂载，`App.vue` 包 `el-config-provider`。
2. **抽取文案**：从 `common` 起，逐模块把硬编码中文替换为 `t('...')`；建立 `zh-CN` 全量，`en-US` 对齐翻译。
3. **语言切换 UI**：顶栏下拉 + 持久化，验证刷新后保持。
4. **axios 语言头** + 后端 `MessageSource` / `LocaleResolver`。
5. **后端消息改造**：`Result` 与 `BusinessException` 改为 key 驱动，补全两语资源文件。
6. **菜单 i18nKey**：菜单表加字段，前端渲染回退逻辑。
7. **用户偏好落库**：`sys_user.locale` + 登录返回 + 保存接口。
8. **校验消息**、（可选）字典多语言。

---

## 七、注意事项

- **默认与兜底**：无论何种异常路径，最终回退 `zh-CN`，绝不出现空文案或裸 key。
- **翻译完整性**：CI 加一步"语言包键一致性校验"，防止 `en-US` 漏键。
- **不翻译契约**：状态枚举 `ENABLED/DISABLED`、菜单类型 `DIR/MENU/BUTTON`、权限码等 API 契约值恒定，仅在展示层用语言包映射为可读文案。
- **性能**：语言包按需可做懒加载（`import()`），首期语种少可全量打包。
- **全局偏好**：面向用户的默认展示语言为简体中文，与用户全局偏好一致。
