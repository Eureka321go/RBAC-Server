# 附录 · HTTP 协议版本基础

> 通用背景知识（不专属某个阶段）。主线一句话：**HTTP 版本演进 = 不断减少连接开销 + 消除排队阻塞**。

## 一张时间线

| 版本 | 年份 | 一句话 |
|------|------|--------|
| HTTP/0.9 | 1991 | 只能 `GET`、只能拿 HTML，玩具级 |
| HTTP/1.0 | 1996 | 有了请求头、状态码、能传各种文件；但**每次请求都要重新建连接** |
| **HTTP/1.1** | 1997 | **连接复用 + 至今最广泛**，本项目默认就是它 |
| **HTTP/2** | 2015 | **多路复用**，一个连接并发跑多个请求，快很多 |
| **HTTP/3** | 2022 | 底层从 TCP 换成 **QUIC(UDP)**，弱网更快 |

## 前提：请求要先「建连接」

浏览器和服务器通信，得先通过 **TCP 三次握手**建一条「管道」，再在管道里发 HTTP 请求。**建管道有成本**（几次网络往返，HTTPS 还要加 TLS 握手）。HTTP 版本演进，很大程度就是在优化「管道怎么建、怎么用得更划算」。

## HTTP/1.0：每次请求都新建管道（慢）

```
请求图片A：建连接 → 发请求 → 收响应 → 关连接
请求图片B：又建连接 → 发请求 → 收响应 → 关连接
```

一个网页几十个资源（图片/CSS/JS）就要建几十次连接，握手开销巨大。

## HTTP/1.1：连接复用 + 队头阻塞（本项目现在用的）

**① 长连接（Keep-Alive，默认开启）**：一条管道建好后**不关、反复用**，省掉反复握手。
```
建连接 → 请求A → 响应A → 请求B → 响应B → ...（同一条管道）
```

**② 硬伤：队头阻塞（Head-of-Line Blocking）**
同一条管道里请求得**排队一个一个来**——A 没回来 B 只能干等，像单车道被前面慢车堵住。
- 浏览器补救：对同一域名**同时开 6 条管道**并行，但也就 6 条，资源多了还是不够。

> 关联：HTTP/1.1「请求在连接里排队」+ 服务器端「一个请求一根线程」，共同决定了传统 Web 的并发模型（见阶段 3 补充问答的线程模型）。

## HTTP/2：多路复用（质变）

核心一招 **多路复用（Multiplexing）**：**一条管道里同时并发跑很多请求**，互不阻塞。

```
HTTP/1.1： 一条管道 = 单车道，请求排队
HTTP/2：   一条管道 = 多车道高速，请求A/B/C 同时跑，谁先好谁先回
```

把每个请求拆成带编号的「帧(frame)」，在同一连接里交错传输，到对端按编号拼回。好处：一条连接搞定全部请求，不用开 6 条；解决了 HTTP 层队头阻塞。附带优化：**头部压缩(HPACK)**、**服务器推送**（后来少用）。

> ⚠️ HTTP/2 仍有更底层的队头阻塞：它跑在 **TCP** 上，只要**丢一个包**，整条连接所有请求都得等重传——锅在 TCP，HTTP/2 自己解决不了。于是有了 HTTP/3。

## HTTP/3：换掉 TCP，改用 QUIC(UDP)

最大变化在**传输层**：不再用 TCP，改用基于 **UDP** 的 **QUIC** 协议。

- **彻底解决队头阻塞**：各请求流相互独立，一个流丢包不影响其它流。
- **连接建得更快**：TLS 握手与连接握手合并，往返更少，甚至「0-RTT」秒连。
- **连接迁移**：手机 WiFi 切 4G 连接不断（TCP 换网就断）。
- 弱网、移动端体验提升明显。

## 怎么看自己在用哪个版本

- 浏览器 F12 → Network → 右键表头勾出「Protocol」列：`http/1.1`、`h2`(HTTP/2)、`h3`(HTTP/3)。
- 用不用得上高版本，通常由**服务器 + 是否 HTTPS + 中间的 Nginx/CDN** 决定，业务代码基本无感。

## 和本项目的关系

- 本地 `mvn spring-boot:run` 的内嵌 Tomcat 默认走 **HTTP/1.1**，学习开发足够。
- 生产升 HTTP/2 一般**不改 Java 代码**，而是在前面挂 **Nginx / 网关**开启（还需 HTTPS，浏览器只在 HTTPS 下用 h2）。所以对后端 RBAC 逻辑而言，HTTP 版本是**透明**的——Controller/Filter 不用关心底层是 1.1 还是 2。

---

**总纲一句话**：
> **1.0** 每次新建连接（慢）→ **1.1** 连接复用但请求排队 → **2** 一条连接多路并发(解决 HTTP 层排队) → **3** 换 QUIC/UDP(解决 TCP 层排队 + 弱网更快)。主线始终是「**减少连接开销 + 消除排队阻塞**」。
