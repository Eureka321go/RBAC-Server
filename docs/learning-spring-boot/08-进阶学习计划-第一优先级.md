## 单元 1 · 事务原理与并发控制（07 §2.1 · 阶段 7A · 最该先学）

**学习目标**：能解释项目里每一个事务边界；能说清同一条工作流待办被两个人同时审批时，最终会发生什么、为什么不会重复推进。

**读完你能回答**：`@Transactional` 什么时候不生效？裸 `@Transactional` 和 `@Transactional(rollbackFor = Exception.class)` 差在哪？乐观锁、悲观锁、唯一约束各自解决什么？

### 1.1 要读的项目真实代码（锚点）

| 文件 : 位置 | 看什么 |
|-------------|--------|
| `workflow/engine/WorkflowEngineImpl.java` `start()` L69 / `approve()` L99 / `reject()` L116 / `transfer()` L140 / `withdraw()` L165 | **规范写法**：状态机核心流转全部 `@Transactional(rollbackFor = Exception.class)` |
| `workflow/definition/service/DefinitionService.java` L70 / L88 / L125 | 同上规范写法 |
| `system/user/service/UserService.java` `create()` L111 / `update()` L133 / `assignRoles()` L194 | **反例对照**：裸 `@Transactional`，没写 `rollbackFor` |
| `system/role/service/RoleService.java` L129 / L149、`system/dict/service/DictService.java` L82 | 同上裸写法 |
| `workflow/instance/entity/WfProcessInstance.java` L34-35 `@Version private Integer version` | 全项目**唯一**的乐观锁字段（会签并发保护） |
| `common/config/MybatisPlusConfig.java` L19 `@Bean` / L25 `OptimisticLockerInnerInterceptor` / L28 `PaginationInnerInterceptor` | 乐观锁插件注册——**注意乐观锁在分页插件之前** |
| `workflow/engine/WorkflowEngineImpl.java` `updateInstanceWithLock()` L287 | 乐观锁触发点：`updateById` 返回 0 行 → 抛 `workflow.instance.concurrentModified` |
| `workflow/engine/WorkflowEngineImpl.java` `requirePendingTaskOfCurrentUser()` L296 | 并发**第一道守卫**：任务存在 + 状态 PENDING + 当前用户是审批人 |
| `resources/db/schema.sql` `uk_user_username` L42 / `uk_wf_def_key_ver` L238 等 | 唯一约束兜底（多数带 `deleted` 列，配合逻辑删除） |

> 🔑 本单元最值钱的教学点：**同一个仓库里两种事务写法并存**。工作流写 `rollbackFor = Exception.class`，system 模块写裸 `@Transactional`。学完你要能说清：默认只对 `RuntimeException` 回滚，所以裸写法一旦抛受检异常（`Exception`）事务**不回滚**——这就是为什么要显式写 `rollbackFor`。

### 1.2 原理清单（必须吃透）

- 事务为什么依赖 Spring AOP **代理**（→ 留到单元 4 讲透"代理"，这里先记结论）。
- **同类内部方法自调用**为什么导致事务失效。
- 传播行为：`REQUIRED` vs `REQUIRES_NEW`（各自何时用）。
- 隔离级别：读未提交 / 读已提交 / 可重复读 / 串行化的差异。
- 默认回滚规则：只回滚 `RuntimeException` / `Error`；受检异常默认**不回滚** → 对照裸 `@Transactional` 的隐患。
- 乐观锁（`@Version`）、悲观锁（`for update`，项目**未用**）、数据库唯一约束，三者分别解决什么。

### 1.3 动手实践

以"同一待办被并发审批"为案例（`TaskService.approve` → `WorkflowEngineImpl.approve`）：写一个并发测试，两个线程同时审批同一个 `taskId`，观察 `@Version` 冲突导致 `updateInstanceWithLock` 抛 `concurrentModified`，确认前端拿到明确的业务错误码而不是 500。

### 1.4 自检问题（对齐 07 §6）

1. 为什么 `@Transactional` 加在某些方法上不生效？（举本项目一个自调用可能踩坑的场景）
2. 两个请求同时审批一条待办，最终会发生什么？`requirePendingTaskOfCurrentUser` 和 `@Version` 各挡住了哪一层？
3. `UserService.create` 的裸 `@Transactional` 在什么异常下不回滚？怎么改安全？

### 1.5 面试怎么问

- **Q：`@Transactional` 什么情况下失效？** 要点：非 public 方法、同类自调用（走不到代理）、异常被自己 catch 掉、默认不回滚受检异常。举例：本项目 system 模块裸 `@Transactional`，若方法内抛受检异常则不回滚。
- **Q：乐观锁和唯一约束有什么区别？** 要点：乐观锁靠版本号在"更新时"发现并发（`@Version`），唯一约束靠 DB 在"写入时"拦重复。举例：工作流实例用 `@Version` 防会签重复推进，`sys_user` 用 `uk_user_username` 防重名。
- **Q：两个人同时审批同一任务怎么保证不重复？** 要点：先业务校验（PENDING + 是审批人），再乐观锁兜底，`updateById` 返回 0 即失败回滚。

## 单元 2 · 异步任务与线程池（07 §2.2）

**学习目标**：能说清项目为什么把日志写成异步、这么写有什么隐患、生产上该怎么补。

**读完你能回答**：默认线程池为什么不能直接上生产？`@Async` 方法抛异常去哪了？异步线程里为什么取不到当前登录人？

### 2.1 要读的项目真实代码（锚点）

| 文件 : 位置 | 看什么 |
|-------------|--------|
| `RbacServerApplication.java` L12 `@EnableAsync` | 异步能力总开关（挂在启动类上） |
| `system/log/service/LogService.java` `recordLogin()` L35 / `recordOperation()` L47 | 两个 `@Async` 方法（类注释：写入异步、避免拖慢主流程） |
| `system/log/aspect/OperationLogAspect.java` `fillOperator()` L73 | **规避上下文丢失的巧思**：在**同步线程**里先 `SecurityUtils.getLoginUserOrNull()` 取好操作人，填进 `SysOperationLog`，再传给 `@Async` 方法 |

> 🔑 项目**没有**自定义线程池、`TaskDecorator`、MDC/traceId 传递。它用了另一条路避开"异步取不到登录人"：**操作人在同步切面里先取好再传进去**，异步线程不再依赖 `SecurityContext`。这是理解"上下文为什么会丢、怎么绕过"的绝佳真实样本。

### 2.2 原理清单

- 核心线程数 / 最大线程数 / 队列容量 / 拒绝策略。
- Spring 默认执行器为什么不适合生产（→ **延伸练习**：项目当前正是用默认执行器）。
- `@Async` 方法的异常为什么不会自动返回给调用方（需要 `AsyncUncaughtExceptionHandler`）。
- 事务**提交前**就启动异步任务会有什么问题。
- `SecurityContext`、traceId 等上下文如何跨线程传递（对照项目"同步先取好"的规避法）。
- 应用停止时如何等待队列里的任务跑完（优雅停机）。

### 2.3 动手实践（延伸/改进）

为操作日志配一个**独立的 `ThreadPoolTaskExecutor`**（自定义线程名、队列、拒绝策略、`AsyncUncaughtExceptionHandler`），把 `@Async` 指向它；再验证应用关闭时队列里的日志会不会丢。

### 2.4 自检问题

1. 项目现在用的是哪种线程池？直接上生产有什么风险？
2. `recordOperation` 内部抛异常，调用它的业务方法能感知吗？为什么？
3. 如果 `fillOperator` 不在同步线程先取操作人，而是让异步方法自己去取 `SecurityContext`，会发生什么？

### 2.5 面试怎么问

- **Q：为什么不建议直接用 `@Async` 默认线程池？** 要点：默认是 `SimpleAsyncTaskExecutor`（每次新建线程、不复用、无上限），可能压垮系统；生产要自定义有界线程池 + 拒绝策略。
- **Q：`@Async` 方法抛异常怎么处理？** 要点：返回 `void` 时异常不会传回调用方，要配 `AsyncUncaughtExceptionHandler`；返回 `Future` 时在 `get()` 时抛出。
- **Q：异步里怎么拿当前登录用户？** 要点：`SecurityContext` 默认不跨线程；本项目的做法是同步线程先取好再传参（`OperationLogAspect.fillOperator`），另一种是 `DelegatingSecurityContext` / `TaskDecorator`。

## 单元 3 · 配置体系与多环境（07 §2.3）

**学习目标**：能说清配置从哪来、优先级怎么排、密钥怎么不进 git，并能把项目改造成类型安全、多环境。

**读完你能回答**：开发 / 测试 / 生产为什么不能共用一份库和密钥？`@Value` 和 `@ConfigurationProperties` 怎么选？

### 3.1 要读的项目真实代码（锚点）

| 文件 : 位置 | 看什么 |
|-------------|--------|
| `resources/application.yml` L66 `rbac:` / L67 `jwt:` | 自定义配置块（唯一一份 yml，无 profile 拆分） |
| `resources/application.yml` L69 `secret: ${RBAC_JWT_SECRET:...默认值...}` | **占位符默认值**：本地用默认、生产用环境变量覆盖。DB/Redis 同款 `${DB_HOST}`/`${REDIS_HOST}` |
| `security/JwtTokenProvider.java` 构造器（`@Value("${rbac.jwt.secret}")` 等） | 读取方式：**全用 `@Value`** |
| `system/user/service/UserService.java` `@Value("${rbac.security.default-password:123456}")` | `@Value` 带默认值写法 |

> 🔑 项目**全部用 `@Value`，没有一个 `@ConfigurationProperties` POJO，也没有 `application-dev/test/prod`**。这正是"`@Value` vs `@ConfigurationProperties`""三环境拆分"的现成改造切入点。

### 3.2 原理清单

- 配置文件 / 环境变量 / 命令行参数的**优先级**顺序。
- `application-{profile}.yml` 机制，`spring.profiles.active` 怎么切。
- `@Value` vs `@ConfigurationProperties` 的取舍（散读 vs 成组 + 校验 + 类型安全）。
- 配置校验（`@Validated` + JSR-303）、默认值、类型安全。
- 密钥、密码等敏感配置如何与代码仓库分离（呼应项目"安全红线"：`application.yml`、`deploy/.env` 里的密码仅限本地）。

### 3.3 动手实践（延伸/改进）

把 `rbac.jwt.*` 抽成类型安全的 `@ConfigurationProperties` 配置类（如 `JwtProperties`，含 `secret/accessTtl/refreshTtl` + `@Validated` 校验），`JwtTokenProvider` 改注入这个类；再拆出 `application-dev.yml` / `application-test.yml` / `application-prod.yml` 三套。

### 3.4 自检问题

1. 为什么开发、测试、生产不能共用一份数据库和密钥配置？
2. `${RBAC_JWT_SECRET:默认值}` 这种写法，本地和生产分别读到的是什么？
3. `rbac.jwt` 有 3 个字段，用 `@ConfigurationProperties` 比散着写 `@Value` 好在哪？

### 3.5 面试怎么问

- **Q：Spring Boot 配置优先级？** 要点：命令行参数 > 环境变量 > `application-{profile}.yml` > `application.yml`（记大方向：越"外部/具体"越优先）。
- **Q：`@Value` 和 `@ConfigurationProperties` 怎么选？** 要点：单个零散值用 `@Value`；一组相关配置、需要校验/类型安全/IDE 提示用 `@ConfigurationProperties`。举例：本项目 `rbac.jwt` 三个字段散用 `@Value`，更适合收成一个配置类。
- **Q：密钥怎么不进 git？** 要点：占位符 + 环境变量覆盖（`${RBAC_JWT_SECRET:...}`），`.env` 不入库，生产从环境注入。

## 单元 4 · 自动配置 / Bean 生命周期 / 代理（07 §2.4）

**学习目标**：能独立排查"配置没生效""Bean 没创建""AOP 没拦到"这类问题，并理解 starter 为什么"加个依赖就能用"。

**读完你能回答**：为什么 AOP / 事务拦不到同类自调用的方法？（回接单元 1）怎么查一个 Bean 为什么没被创建或冲突了？

### 4.1 要读的项目真实代码（锚点）

| 文件 : 位置 | 看什么 |
|-------------|--------|
| `security/config/SecurityConfig.java` L21（+`@EnableMethodSecurity` L22 / `@Bean securityFilterChain` L45 / `@Bean passwordEncoder` L66） | 最典型的 `@Configuration` + `@Bean` |
| `common/config/MybatisPlusConfig.java` L16 / `@Bean` L19 | 插件 Bean（乐观锁 + 分页） |
| `common/config/LocaleConfig.java` L20（`localeResolver` L24 / `getValidator` L38） | `getValidator` 把 `MessageSource` 接进 Bean Validation——**校验消息国际化的根** |
| `common/config/RedisConfig.java` L17 / `@Bean redisTemplate` L20 | `GenericJackson2JsonRedisSerializer` + 多态白名单 `BasicPolymorphicTypeValidator` L36 |
| `common/config/AuditMetaObjectHandler.java` L14 实现 `MetaObjectHandler`（`insertFill` L17 / `updateFill` L33） | **Bean 参与框架生命周期**的范例：MyBatis-Plus 回调它自动填审计字段 |

> 🔑 项目**没有**自定义 starter、没有 `@ConditionalOn*`、没有 `@PostConstruct`/`@PreDestroy`。这些正好留作延伸练习——写一个"审计日志 starter"能把自动配置的整套机制（条件装配 + 默认 Bean + 允许业务覆盖）走一遍。

### 4.2 原理清单

- 一个 starter 为什么只加依赖就能工作（自动配置 + `spring.factories` / `AutoConfiguration.imports`）。
- `@Configuration`、`@Bean`、组件扫描分别何时用。
- `@ConditionalOnClass`、`@ConditionalOnMissingBean` 如何决定 Bean 是否创建（**允许业务覆盖默认 Bean** 的关键）。
- Bean 从实例化 → 依赖注入 → 初始化（`@PostConstruct`）→ 销毁（`@PreDestroy`）经历哪些阶段。
- 循环依赖为什么发生，为什么不该依赖框架"帮忙解决"。
- **Spring AOP 通常只能拦截"经过代理的 public 方法"** → 直接解释单元 1 的事务/日志切面为什么对同类自调用、private 方法失效。
- 怎么看自动配置条件报告（`--debug` 或 Actuator `conditions`）排查 Bean 冲突/缺失。

### 4.3 动手实践（延伸/改进）

写一个小型"审计日志 starter"：提供默认的日志落库 Bean，并用 `@ConditionalOnMissingBean` 允许业务项目覆盖它。

### 4.4 自检问题

1. 为什么 `@Transactional` / AOP 切面拦不到同类里 `this.xxx()` 的自调用？（结合单元 1）
2. `AuditMetaObjectHandler` 是怎么被框架"叫起来"自动填 `createdAt` 的？它算哪种 Bean？
3. 想让业务方能覆盖 starter 里的默认 Bean，该用哪个 `@ConditionalOn*`？

### 4.5 面试怎么问

- **Q：Starter 的原理是什么？** 要点：自动配置类 + 条件注解 + `META-INF/.../AutoConfiguration.imports`，引入依赖即被扫描装配。
- **Q：为什么 AOP / 事务对自调用失效？** 要点：代理只包了"从外部进来"的调用；`this.method()` 走的是原始对象，绕过代理。
- **Q：怎么排查一个 Bean 没被创建？** 要点：看自动配置条件报告（`conditions`）、检查 `@ConditionalOn*`、组件扫描路径、是否被同名 Bean 覆盖。

## 单元 5 · Spring MVC 完整执行链（07 §2.5）

**学习目标**：能画出一次工作流审批请求从进入到响应经过的每一环，并让所有失败情况都以统一格式返回。

**读完你能回答**：Filter、Interceptor、AOP、ControllerAdvice 各自该管什么？带 JWT + 权限注解的 Controller 怎么测？

### 5.1 要读的项目真实代码（锚点）

| 文件 : 位置 | 看什么 |
|-------------|--------|
| `security/JwtAuthenticationFilter.java` L24（`OncePerRequestFilter`，`doFilterInternal` L37） | **Filter 层**：解析 Bearer → 校验 Redis 会话 → 写 `SecurityContext`。注册顺序见 `SecurityConfig` L61 `addFilterBefore(...)` |
| `common/web/GlobalExceptionHandler.java` L19 `@RestControllerAdvice` | **统一错误协议**：`BusinessException` L24 / `MethodArgumentNotValidException`（取首个字段错误）L29 / `AccessDeniedException`→403 L36 / 兜底 `Exception`→500 L42 |
| `common/Result.java` L14 | 统一响应 `code/message/data`，message 走 i18n |
| `common/exception/BusinessException.java` | 业务异常类 |
| `AuthController` L34/L46 及各 `*Controller` 的 `@Valid @RequestBody` | 参数校验入口；校验消息 i18n 由 `LocaleConfig.getValidator` L38 接入 |
| `system/log/aspect/OperationLogAspect.java` L34 `@Around` | **AOP 层**：环绕通知记录耗时/结果/操作人（对比"为什么不用 Interceptor"） |

> 🔑 差异点要讲清：项目**没有 `HandlerInterceptor`**（操作日志用 AOP 而非拦截器）、**没有全局 MVC Jackson 定制**（`RedisConfig`、`RestAuthErrorWriter` 各自持独立 `ObjectMapper`，注释明确"避免动全局 MVC 序列化"）、**没有文件上传下载**。这几处正好用来讲 Filter / Interceptor / AOP / ControllerAdvice 的**职责边界**。

### 5.2 原理清单

- Filter、Interceptor、ControllerAdvice、AOP 的**执行顺序与职责边界**（谁在 Spring 之外、谁在 handler 前后、谁包业务方法、谁兜异常）。
- 参数解析、JSON 反序列化、响应序列化的过程。
- Jackson 的日期 / 枚举 / 空值 / 未知字段策略。
- 分组校验（`@Validated(Group.class)`）+ 自定义校验注解。

### 5.5 面试怎么问

- **Q：Filter / Interceptor / AOP / ControllerAdvice 区别？** 要点：Filter 在 Servlet 层（最外，能改请求/响应流）；Interceptor 在 handler 前后（拿得到 handler）；AOP 包 Spring Bean 方法（细到方法级）；ControllerAdvice 统一收异常/响应。举例：本项目 JWT 用 Filter、日志用 AOP、异常用 `@RestControllerAdvice`。
- **Q：带 JWT + 权限注解的 Controller 怎么测？** 要点：`@WebMvcTest` + MockMvc + Spring Security Test（`@WithMockUser` / 模拟 token），断言状态码和 `Result` 结构。
- **Q：统一异常怎么设计？** 要点：`@RestControllerAdvice` 收各类异常 → 映射成统一 `Result` + 合适 HTTP 状态码；业务异常带业务 code，校验异常取字段消息。
