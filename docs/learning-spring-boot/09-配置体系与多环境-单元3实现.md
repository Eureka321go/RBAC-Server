## 一、配置从哪来、优先级怎么排

Spring Boot 的配置是**多来源叠加**的，同名 key 谁生效由优先级决定。记大方向：**越"外部/具体"越优先**。常用的从高到低：

1. **命令行参数** `--server.port=18080`
2. **环境变量 / 系统属性** `SPRING_PROFILES_ACTIVE=prod`、`RBAC_JWT_SECRET=...`
3. **`application-{profile}.yml`**（激活的 profile）
4. **`application.yml`**（公共默认）

本项目大量用**占位符 + 默认值**语法把「环境变量」和「文件默认值」这两层接起来：

```yaml
url: jdbc:mysql://${DB_HOST:localhost}:${DB_PORT:3306}/rbac...
#                  └── 读环境变量 DB_HOST，读不到就用 localhost
secret: ${RBAC_JWT_SECRET:rbac-server-default-secret-key-...}
#         └── 本地读默认值；生产在环境里注入 RBAC_JWT_SECRET 覆盖它
```

- **本地开发**：不设任何环境变量 → 全用冒号后的默认值，开箱即跑。
- **生产**：`deploy/.env` / 容器环境注入真实值 → 覆盖默认值，密钥不进代码仓库。

### profile 怎么切

`application.yml` 里一行决定激活哪个 profile：

```yaml
spring:
  profiles:
    active: ${SPRING_PROFILES_ACTIVE:dev}   # 默认 dev，可被环境变量覆盖
```

切换方式（任选其一，优先级同上表）：

```bash
# 环境变量（部署最常用）
SPRING_PROFILES_ACTIVE=prod java -jar rbac-server.jar
# 命令行参数
java -jar rbac-server.jar --spring.profiles.active=test
# mvn 本地
mvn spring-boot:run -Dspring-boot.run.profiles=test
```

激活 `prod` 后，Spring 会用 `application.yml`（公共） **叠加** `application-prod.yml`（覆盖），后者同名 key 生效。

## 二、`@Value` vs `@ConfigurationProperties`：为什么要改

| 维度 | `@Value("${...}")` | `@ConfigurationProperties` |
|------|--------------------|-----------------------------|
| 适合 | 单个、零散的值 | 一**组**相关配置 |
| 类型安全 | 字符串魔法，散在各处 | 强类型 POJO，IDE 有提示 |
| 校验 | 无（跑起来才知道错） | `@Validated` + JSR-303，**启动即校验** |
| 复用 | 每处重复写 key 字符串 | 注入一个对象，处处可用 |
| 缺省风险 | key 写错只有运行到才炸 | 绑定/校验失败**启动即 fail-fast** |

本项目 `rbac.jwt` 有 3 个字段、还散在两个类里读，正是"一组相关配置"，用 `@ConfigurationProperties` 收编后：

- **类型安全**：`getJwt().getAccessTtl()` 直接是 `long`，不再是每处 `@Value` 手写字符串 key。
- **启动即校验**：密钥太短（HMAC-SHA256 要求 ≥256bit）、TTL 非正数、default-password 为空，都会在**启动时**被 `@Validated` 拦下，而不是等第一个用户登录才炸。

## 三、逐段读改造后的代码

### 3.1 `RbacProperties`：类型安全 + 校验

```java
@Validated                              // ← 开启 JSR-303 校验，违反即启动失败
@ConfigurationProperties(prefix = "rbac")   // ← 绑定 rbac.* 这棵子树
public class RbacProperties {

    @Valid private final Jwt jwt = new Jwt();          // ← @Valid 让嵌套对象也被校验
    @Valid private final Security security = new Security();

    public static class Jwt {
        @NotBlank
        @Size(min = 32, message = "JWT 密钥长度至少 32 字节（HMAC-SHA256 需 ≥256bit）")
        private String secret;                          // rbac.jwt.secret
        @Positive private long accessTtl;               // rbac.jwt.access-ttl
        @Positive private long refreshTtl;              // rbac.jwt.refresh-ttl
        // getter / setter ...
    }

    public static class Security {
        @NotBlank private String defaultPassword;       // rbac.security.default-password
        // getter / setter ...
    }
}
```

要点：

- **前缀 → 字段的映射**：`rbac.jwt.access-ttl`（yml 里 kebab-case）自动绑到 `Jwt.accessTtl`（Java camelCase），这叫 **relaxed binding**，不用手写映射。
- **`@Valid` 不能省**：外层 `@Validated` 只校验直接字段；嵌套的 `Jwt`/`Security` 内部约束要靠字段上的 `@Valid` 级联进去。
- **`@Size(min = 32)` 是真实约束**：`JwtTokenProvider` 用 `Keys.hmacShaKeyFor(secret)` 生成 HMAC-SHA256 密钥，jjwt 要求密钥 ≥256bit（32 字节），否则运行时抛异常。把这条前移成启动校验，等于"配错密钥当场就报"。

### 3.2 启用绑定：`@ConfigurationPropertiesScan`

```java
@SpringBootApplication
@ConfigurationPropertiesScan   // ← 扫描并注册所有 @ConfigurationProperties 类
@MapperScan("com.rbac.**.mapper")
public class RbacServerApplication { ... }
```

对比另一种写法 `@EnableConfigurationProperties(RbacProperties.class)`——那个要**逐个列出**配置类；`@ConfigurationPropertiesScan` 按包扫描，新增配置类不用再改启动类。二选一即可，本项目用扫描式。

### 3.3 `JwtTokenProvider`：3 个 `@Value` → 一个对象

```java
// 改造前：构造器塞 3 个 @Value
public JwtTokenProvider(
        @Value("${rbac.jwt.secret}") String secret,
        @Value("${rbac.jwt.access-ttl}") long accessTtlSeconds,
        @Value("${rbac.jwt.refresh-ttl}") long refreshTtlSeconds) { ... }

// 改造后：注入类型安全对象
public JwtTokenProvider(RbacProperties properties) {
    RbacProperties.Jwt jwt = properties.getJwt();
    this.key = Keys.hmacShaKeyFor(jwt.getSecret().getBytes(StandardCharsets.UTF_8));
    this.accessTtlSeconds = jwt.getAccessTtl();
    this.refreshTtlSeconds = jwt.getRefreshTtl();
}
```

内部字段（`key` / `accessTtlSeconds` / `refreshTtlSeconds`）和对外的 `getAccessTtlSeconds()` 等方法**签名不变**，所以 `AuthService` 那边零改动——这是"收编配置但不外溢"的好处。

### 3.4 `UserService`：顺手把最后一处 `@Value` 也收编

```java
// 改造前
@Value("${rbac.security.default-password:123456}") String defaultPassword
// 改造后
RbacProperties rbacProperties   // 构造器注入
this.defaultPassword = rbacProperties.getSecurity().getDefaultPassword();
```

至此项目**再无自定义 `rbac.*` 的 `@Value`**，配置读取口径统一。

## 四、多环境拆分

### 4.1 拆分结构

```
application.yml          # 公共：server / messages / mybatis-plus / rbac 默认值 / 默认 profile
├─ application-dev.yml   # 本地开发（默认激活）
├─ application-test.yml  # 集成 / QA
└─ application-prod.yml  # 生产
```

**分层原则**：与环境无关的（端口、i18n、逻辑删除、MyBatis 映射、jwt 的 ttl/默认密码）留公共；**每个环境不一样的**（DB/Redis 连接、密钥、SQL 初始化策略、连接池大小、日志级别）下沉到各 profile。

### 4.2 三环境差异一览

| 维度 | dev | test | prod |
|------|-----|------|------|
| 数据库 | `rbac`（localhost 默认值） | `rbac_test`（独立库） | `${DB_HOST}` **无默认** |
| Redis database | 0 | 1（与 dev 隔离） | 0 |
| JWT 密钥 | 允许默认值 | 固定测试密钥 | `${RBAC_JWT_SECRET}` **无默认** |
| Access/Refresh TTL | 2h / 7d | **60s / 300s**（便于验证过期） | 2h / 7d |
| `spring.sql.init` | always（建表+灌数据） | always | **never**（库表须已存在） |
| Hikari 最大连接 | 20 | 8 | 50 |
| SQL 打印 | 开（StdOut） | 关 | 关 |
| 日志级别 | debug | info | warn/info |

### 4.3 prod 的"完整差异化"设计

生产 profile 的核心是**不让生产悄悄用上开发默认值**：

```yaml
# application-prod.yml（节选）
spring:
  datasource:
    url: jdbc:mysql://${DB_HOST}:${DB_PORT:3306}/${DB_NAME:rbac}?...  # DB_HOST 无默认
    username: ${DB_USER}          # 无默认
    password: ${DB_PASSWORD}      # 无默认
  sql:
    init:
      mode: never                 # 生产不自动建表/灌种子数据
rbac:
  jwt:
    secret: ${RBAC_JWT_SECRET}    # 无默认 → 配合 @NotBlank 缺失即 fail-fast
```

- **敏感/连接关键项**（`DB_HOST`/`DB_USER`/`DB_PASSWORD`/`REDIS_HOST`/`REDIS_PASSWORD`/`RBAC_JWT_SECRET`）**只读环境变量、不给默认值**：缺一个，启动就失败，绝不带病上线。
- **结构性、低风险项**（`DB_PORT`/`DB_NAME`/`REDIS_PORT`）给默认值，减少必填项。
- **`sql.init.mode: never`**：生产库表由运维/迁移工具管理，应用启动不碰 schema/data。

> ⚠️ **对现有线上部署的影响**：线上目前没设 `SPRING_PROFILES_ACTIVE` → 会走**默认 dev**，行为和改造前一致，**不受影响**。若要把线上切成 prod，需先在阿里云 `deploy/.env` 备齐上面那批环境变量，再以 `SPRING_PROFILES_ACTIVE=prod` 启动；prod 下 `sql.init=never` 要求库表已存在（已部署过即满足）。

## 五、密钥不进 git & fail-fast 演示

**不进 git**：代码仓库里只有占位符和"仅限本地"的默认值（对齐项目安全红线：`application.yml`、`deploy/.env` 里的密码仅限本地）。真正的生产密钥通过环境变量注入，`.env` 不入库。

**fail-fast 怎么触发**：`@Validated` 的 `RbacProperties` 会在**应用启动阶段**绑定并校验。以下任一情况都会让启动直接失败、给出清晰报错，而不是"跑起来某个请求才炸"：

- prod 下没设 `RBAC_JWT_SECRET` → `secret` 为空 → `@NotBlank` 失败。
- 密钥被改得不足 32 字节 → `@Size(min = 32)` 失败。
- 误把 `access-ttl` 配成 0 或负数 → `@Positive` 失败。

启动失败时 Spring Boot 会打印类似 `Binding to target ... failed` / `Property: rbac.jwt.secret / Reason: 不能为空` 的报告，定位一目了然。

## 六、回答 08 单元 3 的自检问题

1. **为什么开发、测试、生产不能共用一份库和密钥？**
   数据隔离（测试的脏数据不能污染生产、开发建表不能动生产库）、密钥隔离（一处泄露不牵连全环境）、行为隔离（dev 打 SQL/短 TTL 方便调试，prod 收敛日志/正常 TTL）。本项目用 dev=`rbac`、test=`rbac_test`、prod=`${DB_HOST}` 三套数据源 + 各自密钥体现。

2. **`${RBAC_JWT_SECRET:默认值}` 本地和生产分别读到什么？**
   本地不设该环境变量 → 读冒号后的默认值（仅供开发）；生产在 `.env`/容器里注入 `RBAC_JWT_SECRET` → 读到真实密钥并覆盖默认值。而 prod profile 里我们进一步写成**无默认**的 `${RBAC_JWT_SECRET}`，逼它必须由环境提供。

3. **`rbac.jwt` 三个字段用 `@ConfigurationProperties` 比散写 `@Value` 好在哪？**
   成组管理、强类型、IDE 提示、可加 `@Validated` 启动即校验、多处注入同一对象不再重复写 key 字符串。本项目把 secret 的"≥32 字节"这条硬约束前移成启动校验，就是典型收益。
