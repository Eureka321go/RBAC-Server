## 一、这是在做什么

给一位**已读完 `docs/learning-spring-boot/`（8 篇）和 `docs/learning-docker/`（9 篇）、正在读 `docs/learning-mysql/`** 的学习者，写一套 nginx 学习文档。文档放在 `docs/learning-nginx/`。

完整计划见：`~/.claude/plans/nginx-declarative-moon.md`。

### 和前几套的关系（重要）

本套面临的问题和 **MySQL 那套一模一样**：**项目里的素材只覆盖了知识点的一小半。**

- **项目有真素材的**：`frontend/nginx.conf` 那 45 行（进程模型、gzip、root、location 匹配、try_files、proxy_pass、四个 proxy_set_header）、`deploy/config/nginx/nginx.conf` 那 39 行（遗留）、`frontend/Dockerfile`、compose 里的两个服务、`Caddyfile`。
- **项目完全没有的**：TLS 全家桶、rewrite、负载均衡、限流、缓存、`alias`、正则 location、`keepalive`、自定义 `log_format`。

所以方法论和 MySQL 那套同构，只是叫法不同：

| | MySQL 套 | **nginx 套（本套）** |
|---|---|---|
| 方法 | 考点为主线，项目真表当实验台 | **项目配置为锚点，向外扩展到通用能力** |
| 补足手段 | `rbac_lab` 实验库灌数据实跑 | **"为什么这里没写"的对照配置**（因为练习不跑容器，见下） |

**具体讲法**：每讲到一个项目里真实存在的指令，就把这个指令的**完整能力边界**一起讲透；项目里没用上但该会的，作为"**如果不用 caddy / 如果要加缓存，得写成什么样**"的对照补上。

## 二、学习者偏好（务必遵守）

- **不用生活化类比**：不用做菜、宴席、集装箱这类比方，用准确技术定义和项目实例。（⚠️ 注意 `learning-docker/00`、`01` 实际用了集装箱/菜谱类比，那是规则确立**之前**写的，**别参照它们**，以本条为准。）
- **练习全部是思考题**（本套的明确决策）：**不跑容器、不敲命令**。学习者本机只跑着 `rbac-mysql` / `rbac-redis`，backend/frontend/caddy 本地都没跑。所有练习都设计成读配置、推结果、排错推理。
- **只写不改**（本套的明确决策）：发现的项目问题**全部写成教学案例 + 整改建议，不动任何代码**。整改清单见 `06 §7`。
- **语言**：解释全用简体中文；指令、字段名、文件路径保持原样。
- **不虚构**：贴的每个片段动笔前先 `Read` 核对，不凭记忆默写。
- **节奏**：⚠️ **本套是学习者明确要求「一次生成完，不要逐节确认」的**（原话："文档一次生成不用询问我"），这**覆盖了** `learning-docker`/`learning-mysql` HANDOFF 里"一次只写一节，写完停下等确认"的默认约定。**后续维护若无新指示，回到默认的逐节确认。**
- **答疑要存档**：学习者实操中问的真实问题 → 整理成「课堂答疑」追加到对应章节末尾（`learning-docker/01`、`03` 有现成示例）。

## 三、每节统一模板

1. 开头：一句话学习目标 +「读完你能……」
2. 先给技术定义、执行模型、使用边界，**再**用项目配置证明
3. 项目实证：贴真实片段**逐行讲每处为什么这么写**
4. 「指令 ↔ 本项目配置 ↔ 实际作用」对照表
5. 关键结论用 `> 🔑` 引用块突出
6. 末尾固定四块，顺序不变：`## 动手练习`（全思考题）→ `## 自检问题` → `## 承上启下` → `## 附：答案与解析`
7. 答案区用 `<details><summary><b>题干</b></summary>` 折叠（避免滚动剧透），开头一句"建议先自己想一遍再点开"

**格式约定**：
- 一级标题 `# NN · 标题`（用 `learning-docker` 后期风格，**不用** `# 阶段 N ·`）
- 层级只到三层：`#` → `## 一、二、三…`（中文数字）→ `### N.1`（阿拉伯）
- 附录另立体例：`> **这不是教程，是速查。**` 开篇，无练习/自检/答案区，三列表 + 每条回指章节

> ⚠️ **本套没有 `## 面试怎么问` 栏目**（MySQL 那套有）。因为学习者对 nginx 的诉求是"学配置"，没提面试。**但 nginx 的经典面试点（location 优先级、proxy_pass 斜杠、root vs alias、正向/反向代理、gzip 里为什么没 text/html）已在正文中就地标注为高频面试题。** 若学习者之后要面试导向，可考虑给 `02`/`03`/`04` 补这个栏目。

### ⚠️ 一个跨系列的系统性发现

`06 §7.3` 收的这条线，**和 `learning-docker 07` 第八节是同一个故事**：

> **本项目 nginx 的安全，依赖两个不在 nginx 配置文件里的前提**：`docker-compose.yml:97-98` 的 `expose`（而非 `ports`），以及阿里云安全组只开 22/80/443。**这两个前提没有任何机制保护自己，也不会在被违反时报警。**

`learning-docker 07` 第八节已就 **mysql/redis** 挖出过完全相同的模式（数据库的安全也吊在安全组这根弦上）。**同一个故事，两个受害者** → 说明它是**系统性的，不是偶发的**。

**最便宜的建议**（`06 §7.3`）：在 `docker-compose.yml` 的 `expose` 旁加一行注释，写清"⚠️ 改成 ports 会让 nginx 直接暴露公网且无 TLS"。**它不修任何代码，但让下一个想改的人在改之前就看见。**
