## 一、技术栈规划与取舍

对本地开发阶段，中间件按需分三层，避免一次性把机器塞满：

| 层级 | 组件 | 作用 | 何时启用 |
|------|------|------|----------|
| **核心层** | JDK 21、Maven、Git、Docker | 构建与运行基础 | 立即 |
| **核心层** | MySQL | 存用户 / 角色 / 权限 / 菜单等核心数据 | 立即 |
| **核心层** | Redis | 缓存权限树、Token、登录态、分布式锁 | 立即 |
| **扩展层** | Nginx | 反向代理 / 负载均衡（本地开发可选） | 需要时 |
| **扩展层** | RabbitMQ | 异步审计日志、权限变更广播 | 需要时 |
| **完整层** | Kafka | 海量流式日志（本地一般用不到） | 真需要时 |

**关键取舍：**
- **RabbitMQ 与 Kafka 不要都上**。RBAC 场景消息队列只做异步审计与事件广播，**RabbitMQ 就够**；Kafka 是给海量流式日志设计的，本地是负担。
- Elasticsearch/Kibana 当前没有业务依赖，不纳入项目编排；真正出现全文检索需求时再引入。
- 中间件**一律用 Docker 容器跑**，不在本机原生安装，保证干净、可复现、随时清理。

## 三、安装步骤（可复现）

### 1. JDK 21（LTS）

```bash
brew install openjdk@21
```

JDK 21 是 keg-only，会被已有的 JDK 17 遮蔽。在 `~/.zshrc` 中把 `JAVA_HOME` 指向 21：

```bash
# ~/.zshrc（原来的 -v 17 已替换为下面这行）
export JAVA_HOME="$(brew --prefix openjdk@21)/libexec/openjdk.jdk/Contents/Home"
export PATH=$JAVA_HOME/bin:$PATH
```

> 修改前已自动备份为 `~/.zshrc.bak.<时间戳>`。

生效并验证：

```bash
source ~/.zshrc
java -version   # openjdk version "21.0.11"
```

### 2. Maven

```bash
brew install maven
mvn -version    # Apache Maven 3.9.16，Java version: 21.0.11
```

> 也可直接用 IDEA 内置的 Maven，二者不冲突。

### 3. Docker Desktop

```bash
sudo -v && brew install --cask docker   # 需要输入登录密码建软链
```

装完在「启动台 / 应用程序」里打开一次 **Docker Desktop**，等右上角鲸鱼图标变绿（daemon 就绪）。命令行验证：

```bash
docker version
docker compose version
```

### 4. 中间件（Docker Compose）

所有中间件编排在 `deploy/docker-compose.yml`，凭据在 `deploy/.env`。

```bash
cd deploy

# 仅核心层：MySQL + Redis
docker compose up -d

# 核心 + 扩展层（加 Nginx + RabbitMQ）
docker compose --profile extra up -d

# 全部（再加 Kafka）
docker compose --profile extra --profile full up -d

# 查看状态
docker compose ps

# 停止（保留数据）
docker compose down

# 停止并清空数据卷
docker compose down -v
```
