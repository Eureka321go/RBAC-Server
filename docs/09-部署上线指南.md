# RBAC 系统 —— 部署上线指南

> 记录时间：2026-07-14
> 当前基础：后端 Spring Boot 3.4.1 / 前端 Vue 3.5 + Vite / MySQL 8.4 / Redis 7.4 / Docker Compose
> 本阶段目标：把前后端 + 中间件一起部署到云服务器（VPS），实现「一条命令起全套」，并讲清每一步的原理与安全红线

---

## 一、本地开发 vs 服务器部署的三个核心差异

本地能跑，是因为所有东西都在同一台机器上，全都靠 `localhost` 互相找。搬到服务器要处理三个变化：

1. **前端不再用 `npm run dev`**。dev server 只用于开发热更新。生产要先 `npm run build` 编译成纯静态文件（HTML/JS/CSS），交给 web 服务器（nginx）发布，不需要 Node 运行时。
2. **`localhost` 会失效**。一旦拆成多个容器/进程，`localhost` 只指「当前容器自己」。必须换成对方的网络地址；容器场景下就是 **服务名**（compose 会给同网络的容器做 DNS）。
3. **配置/密码要可外部注入**。本地写死 `rbac_123` 无所谓，公网服务器写死等于裸奔。地址与密码要能从环境变量读取，真密码不进 git。

## 二、目标架构

```
浏览器 ──80/443──> nginx 容器
                    ├── /        → 直接返回 frontend/dist 静态文件（发前端）
                    └── /api/    → 反向代理到 backend 容器:8080
backend 容器 ──> mysql 容器:3306 / redis 容器:6379   （走容器内网，用服务名互联）
```

关键收益：**前后端同域**（浏览器只跟 nginx 打交道），天然无跨域（CORS）问题；数据库/Redis 只在容器内网互通，**不对公网暴露**。

## 三、各部分的原理

### 3.1 前端：build 后就是一堆静态文件

`cd frontend && npm run build` → 产物在 `frontend/dist/`，是纯静态资源，任何能发 HTTP 的服务器指过去即可。

**关键坑：SPA 路由回退。** Vue Router 用前端路由，刷新 `/system/user` 时浏览器会真的向服务器请求这个路径，但该文件不存在（只有 `index.html`）。nginx 必须配 `try_files $uri $uri/ /index.html;`——找不到的路径一律回退到 `index.html`，交给 Vue Router 在浏览器里接管。**不配这条，刷新页面就 404**。

### 3.2 nginx：总入口，按 URL 分流

nginx 是整个部署的唯一入口（占 80/443）。它按路径分流：

- `/`、`/assets/...` → 直接从 `dist` 目录发静态文件。
- `/api/...` → 反向代理转发给后端 Spring Boot。

现有 `deploy/config/nginx/nginx.conf` 里已有 `/api/` 反代那段，但：① 缺发前端静态文件的部分；② `upstream` 指向 `host.docker.internal:8080`（本地开发接法）。上服务器要把反代目标改成后端服务名 `backend:8080`，并补上发前端的 `location /`。

### 3.3 后端：打成 jar，地址改为从环境变量读

`mvn package` 产出一个 jar，`java -jar xxx.jar` 即可运行（用容器则连宿主机 JDK 都不用装）。

`backend/src/main/resources/application.yml` 里三处写死的 `localhost` 必须改成读环境变量：

```yaml
spring:
  datasource:
    url: jdbc:mysql://${DB_HOST:localhost}:3306/rbac?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&useSSL=false&allowPublicKeyRetrieval=true
    username: ${DB_USER:rbac}
    password: ${DB_PASSWORD:rbac_123}
  data:
    redis:
      host: ${REDIS_HOST:localhost}
      password: ${REDIS_PASSWORD:rbac_redis_123}
```

`${DB_HOST:localhost}` 含义：优先读环境变量 `DB_HOST`，读不到就用 `localhost`。这样 **本地不设变量照样跑，服务器设了变量就用服务器地址**，一份配置两处通用。

### 3.4 服务名互联（Docker 内网 DNS）

compose 把所有容器放进同一个虚拟网络（本项目为 `rbac-net`）。网络内 **容器/服务名就是域名**：后端连库直接写 `mysql:3306`，Redis 写 `redis:6379`，nginx 反代写 `backend:8080`，Docker 内置 DNS 负责解析。换机器、重启、IP 变了都不影响——这就是容器化部署省心的原因。

## 四、需要新增/改动的文件清单

| 项 | 文件 | 说明 |
|----|------|------|
| 1 | `backend/Dockerfile`（新增） | 多阶段：Maven 打 jar → 精简 JRE 镜像跑 `java -jar` |
| 2 | `frontend/Dockerfile`（新增） | 多阶段：`npm run build` → 把 `dist` 塞进 nginx 镜像 |
| 3 | `deploy/config/nginx/nginx.conf`（改） | 补 `location /` 发前端；`/api/` 反代目标改 `backend:8080` |
| 4 | `backend/.../application.yml`（改） | 数据库/Redis 地址与密码改为读环境变量（见 3.3） |
| 5 | `deploy/docker-compose.yml`（改） | 新增 `backend`、`frontend` 两个 service，纳入 `rbac-net` |
| 6 | `deploy/.env`（改） | 换强密码，加进 `.gitignore` 不入库 |

### 参考：后端 Dockerfile（多阶段构建）

```dockerfile
# 构建阶段
FROM maven:3.9-eclipse-temurin-21 AS build
WORKDIR /app
COPY pom.xml .
RUN mvn -B dependency:go-offline
COPY src ./src
RUN mvn -B clean package -DskipTests

# 运行阶段
FROM eclipse-temurin:21-jre
WORKDIR /app
COPY --from=build /app/target/*.jar app.jar
EXPOSE 8080
ENTRYPOINT ["java", "-jar", "app.jar"]
```

### 参考：前端 Dockerfile（多阶段构建）

```dockerfile
# 构建阶段
FROM node:22 AS build
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

# 运行阶段：nginx 发静态文件
FROM nginx:1.27
COPY --from=build /app/dist /usr/share/nginx/html
COPY deploy/config/nginx/nginx.conf /etc/nginx/nginx.conf
EXPOSE 80
```

> 说明：前端镜像里内置 nginx 并托管 `dist`，同时承担 `/api/` 反代。也可让前端只发静态文件、由独立 nginx 容器统一入口——两种都行，本指南按「前端镜像即入口」写。

### 参考：nginx.conf 关键片段（发前端 + 反代后端）

```nginx
upstream rbac_backend {
    server backend:8080;   # 改为后端服务名，不再用 host.docker.internal
}

server {
    listen 80;
    server_name _;
    root /usr/share/nginx/html;
    index index.html;

    location /api/ {
        proxy_pass http://rbac_backend;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location / {
        try_files $uri $uri/ /index.html;   # SPA 路由回退，必须有
    }
}
```

### 参考：docker-compose.yml 新增两个 service

```yaml
  backend:
    build: ../backend
    container_name: rbac-backend
    restart: unless-stopped
    environment:
      DB_HOST: mysql
      DB_USER: "${MYSQL_USER:-rbac}"
      DB_PASSWORD: "${MYSQL_PASSWORD:-rbac_123}"
      REDIS_HOST: redis
      REDIS_PASSWORD: "${REDIS_PASSWORD:-rbac_redis_123}"
    depends_on:
      mysql: { condition: service_healthy }
      redis: { condition: service_healthy }
    networks: [rbac-net]
    # 注意：不映射 8080 到宿主机，只让 nginx 走内网反代

  frontend:
    build:
      context: ..
      dockerfile: frontend/Dockerfile
    container_name: rbac-frontend
    restart: unless-stopped
    ports:
      - "80:80"          # 唯一对外暴露的端口
    depends_on: [backend]
    networks: [rbac-net]
```

## 五、服务器上从零到跑起来（云主机 / VPS，有 root）

1. **装 Docker**：`curl -fsSL https://get.docker.com | sh`（自带 compose 插件）。
2. **传代码**：`git clone` 仓库，或本地 `scp -r` 上传。
3. **改配置**：`deploy/.env` 换强密码；`application.yml` 改为读环境变量（见 3.3）。
4. **开安全组端口**：云控制台仅放行 **80**（上 HTTPS 再加 **443**）。⚠️ **3306 / 6379 绝不对公网开放**。
5. **一键起**：`cd deploy && docker compose up -d --build`。
6. **验证**：浏览器访问 `http://服务器公网IP`，能登录、能查数据即成功。
7. **配域名 + HTTPS（可选，强烈建议）**：域名解析到服务器 IP，nginx 挂 SSL 证书（Let's Encrypt 免费证书，或用 Caddy 自动签），之后走 `https://`。

常用运维命令：

```bash
docker compose up -d --build     # 构建并后台启动全套
docker compose ps                # 查看各容器状态
docker compose logs -f backend   # 跟踪后端日志
docker compose down              # 停止（保留数据卷）
docker compose down -v           # ⚠️ 停止并删除数据卷 —— 会清库，慎用
```

## 六、部署安全红线

- **数据库/Redis 端口不出内网**：compose 里 `mysql`/`redis` 服务去掉 `ports:` 映射（容器间靠服务名通信不需要映射到宿主机），只保留 nginx 的 80/443。
- **生产密码不进 git**：`deploy/.env` 加入 `.gitignore`；真密码只放在服务器上。
- **数据持久化**：MySQL 的 `mysql-data` volume 已配好，日常别用 `docker compose down -v`（`-v` 会删数据卷）。
- **SQL 初始化幂等**：首次启动后端会跑 `db/schema.sql` / `db/data.sql`，本项目已用 `IF NOT EXISTS` / `INSERT IGNORE` 保证幂等，反复启动不会覆盖数据。
- 与《04-RBAC后端设计》《CLAUDE.md 安全红线》一致：前端隐藏只是体验，敏感操作后端必须再鉴权；日志/返回禁止出现明文密码、Token。

## 七、上线后可选增强

- **HTTPS 自动续期**：Caddy 或 certbot 定时续 Let's Encrypt 证书。
- **反向代理层加限流 / gzip / 静态缓存**：nginx 配 `gzip on`、静态资源 `expires`。
- **健康检查与自愈**：给 `backend` 加 `healthcheck` + `restart: unless-stopped`。
- **日志与监控**：接入 `docker compose logs` 集中查看，或后续引入 ELK（compose 里已有 `--profile full` 的 ES/Kibana 可复用）。
- **CI/CD**：GitHub Actions 构建镜像并推到服务器，避免每次手动 `--build`。

## 八、本次实战部署记录（阿里云轻量 · 2026-07-14）

> 环境：阿里云轻量应用服务器，Ubuntu 24.04，公网 IP `106.15.89.180`，代码目录 `/root/project/RBAC-Server`。
> 目标：一次 `docker compose up -d --build` 起 mysql + redis + backend + frontend 全套。

### 8.1 服务器准备

```bash
# 装 Docker —— 官方源在国内被墙，必须走阿里云镜像
curl -fsSL https://get.docker.com | sh -s -- --mirror Aliyun
docker -v && docker compose version          # 看到两行版本号才算装好

# 配镜像加速器（拉 mysql/redis/node 等镜像用，单行写避免粘贴折行）
echo '{"registry-mirrors":["https://docker.m.daocloud.io"]}' > /etc/docker/daemon.json
cat /etc/docker/daemon.json                   # 确认是干净的一行 JSON
systemctl restart docker
docker info | grep -A2 "Registry Mirrors"     # 确认源生效
```

阿里云防火墙只放行 **22（SSH）** 和 **80（网页）**；`3306 / 6379` 不对公网开放。

### 8.2 代码上服务器（走 GitHub 私有库 + Deploy Key）

```bash
# 服务器生成密钥，把公钥加到 GitHub 仓库 Settings → Deploy keys（只读，不勾 write）
ssh-keygen -t ed25519 -C "rbac-server-deploy" -f ~/.ssh/id_ed25519 -N ""
cat ~/.ssh/id_ed25519.pub
ssh -T git@github.com                          # 看到 successfully authenticated 即通

# 克隆并切到开发分支（部署文件在 feat/rbac-mvp 上）
cd /root/project
git clone git@github.com:Eureka321go/RBAC-Server.git
cd RBAC-Server && git checkout feat/rbac-mvp
```

> 注意：本地新增/改的部署文件（Dockerfile、compose、nginx、application.yml）必须**先在开发机 commit + push**，服务器才拉得到。

### 8.3 一键构建启动

```bash
cd /root/project/RBAC-Server/deploy
docker compose up -d --build                   # 首次约 13 分钟：现场编译前后端 + 拉镜像
docker compose ps                              # 四个容器 Up / Healthy
docker compose logs --tail=30 backend          # 看到 Started RbacServerApplication 即后端就绪
```

浏览器访问 `http://106.15.89.180`，admin 登录成功 → 全套跑通。

> **构建位置说明**：`--build` 是在**服务器上现场编译打包**（Maven 编译后端 jar、npm build 前端 dist），服务器既是构建机也是运行机。个人/试跑场景最简单；生产建议改为 CI 构建镜像推仓库、服务器只 `pull`（见第七节）。

## 九、踩坑记录与解决

按本次真实遇到的顺序记录，方便下次少走弯路。

| # | 现象 | 原因 | 解决 |
|---|------|------|------|
| 1 | 买服务器时镜像选了「宝塔 Linux 阿里专项版」 | 宝塔会自装 nginx/MySQL 管端口，和全 Docker 方案打架 | 控制台「重装系统」换成纯净 **Ubuntu 22.04/24.04** |
| 2 | `ssh root@IP` → `Permission denied (publickey)` | 服务器只认密钥、没开密码登录 | 控制台「重置密码」并**重启服务器**生效；或用密钥 |
| 3 | `ssh` → `Connection refused` (port 22) | 服务器正在重启/重装，sshd 没起 | 等状态变「运行中」再等 1~2 分钟重连 |
| 4 | `curl get.docker.com` → `Connection reset by peer` | `download.docker.com` 国内被墙 | 安装脚本加 `-s -- --mirror Aliyun` 走阿里云源 |
| 5 | 装完 `docker -v` 提示 `command not found`，误以为装好了 | 那是 Ubuntu 的「可以这样安装」提示，不是成功 | 用官方脚本装，验证要看到 **版本号两行** |
| 6 | 拉 `mysql:8.4` → `not found` / `Interrupted` | 没配镜像加速器 / 单个源抽风 | 在 `daemon.json` 配可用的 registry-mirror |
| 7 | 改 `daemon.json` 后 `systemctl restart docker` 失败 | **多行粘贴被终端折行 + 加空格**，JSON 损坏 | **用单行 `echo` 写**；先 `cat` 确认干净一行再重启 |
| 8 | docker 反复起不来 → `Start request repeated too quickly` | systemd 因连续失败把服务锁了 | 先 `systemctl reset-failed docker` 再 restart |
| 9 | 服务器 `git pull` → `You have divergent branches` | clone 后 checkout 基点和远程分叉 | 部署机没本地改动，直接 `git reset --hard origin/feat/rbac-mvp` |
| 10 | 服务器拉到的代码没有部署文件 | 本地改动没 commit/push 就想在服务器 clone | 先在开发机提交推送，服务器再 `git pull` |
| 11 | 首次 `up --build` 耗时约 13 分钟 | 服务器现场编译 Maven + npm，正常 | 耐心等；后续不改代码重启很快，用 `up -d` 不加 `--build` |

### 经验小结

- **国内服务器三件套必配**：Docker 装用 `--mirror Aliyun`、镜像加速器 `daemon.json`、Maven/npm 换国内源（已写进 Dockerfile）。
- **改 `daemon.json` 一律单行 `echo` 写、`cat` 复核**，多行 heredoc 在某些终端会被折行搞坏。
- **部署机（服务器）当成一次性可重建**：出问题优先 `git reset --hard` 对齐远程、`docker compose down` 重来，别在上面手改。
- **改代码 → 更新线上**的标准循环：开发机 `commit + push` → 服务器 `git pull` → `docker compose up -d --build`。
