# 附录 · 命令速查表

> **这不是教程，是速查。** 忘了原理就点回指的那一节；只想知道敲什么，就看表。
>
> **约定**：带 `docker compose` 的命令**必须在 `deploy/` 目录下跑**（要读到 compose 文件）；`docker xxx` 在哪都行。
> 下面 `<服务>` 指 compose 里的**服务名**（`mysql` / `redis` / `backend` / `frontend` / `caddy`），不是容器名。

---

## 0. 只记两条的话

```bash
docker compose ps                          # 现在什么在跑，健康吗
docker compose logs --tail=50 <服务>        # 它为什么不对劲
```

**90% 的时间你只需要这两条。** 出事了，先敲第二条，别急着重启。（`07` §3.2）

---

## 1. 看状态

| 命令 | 干什么 | 哪节 |
|---|---|---|
| `docker compose ps` | 列**活着的**容器 + 健康状态 + 端口 | `03` |
| `docker compose ps -a` | **连死掉的一起列** ← 容器起不来时用这条 | `07` §3.2 |
| `docker compose config --services` | 这条命令会起哪些服务（**不碰容器**） | `06` §2.4 |
| `docker compose --profile extra config --services` | 加了 profile 之后会起哪些 | `06` §2.4 |
| `docker compose config` | 打印变量替换后的完整 YAML ← 改完文件先看这个 | `03` |
| `docker compose config --profiles` | 这份文件定义了哪些 profile | `06` §2.4 |
| `docker stats` | 谁在吃 CPU / 内存（Ctrl+C 退出） | `07` §2 |
| `docker compose top` | 容器里在跑哪些进程 | — |

> 状态含义：`Up (healthy)` 正常 · `Up (unhealthy)` 进程活着但探针不过（`04`）· `Exited (1)` 启动就崩 · `Restarting` 崩了被反复拉起（`03` 的 `restart:`）

---

## 2. 看日志

| 命令 | 干什么 | 哪节 |
|---|---|---|
| `docker compose logs --tail=50 <服务>` | **最后 50 行 ← 默认就该这么敲** | `07` §3.1 |
| `docker compose logs -f <服务>` | 跟着刷（Ctrl+C 退出） | `07` §3.1 |
| `docker compose logs --since=10m` | 最近 10 分钟，**所有服务**混流（带服务名前缀） | `07` §3.1 |
| `docker compose logs -f --tail=20 <服务>` | 先给 20 行垫底，再跟着刷 ← 看启动最好用 | — |

> ⚠️ **裸 `docker compose logs` 会把终端刷爆**（Spring Boot 启动几百行）。永远带 `--tail`。
>
> 🔑 **日志随容器重建消失。先 `logs` 看明白，再 `up -d --build`。**（`07` §3.2）

## 3. 进容器

| 命令 | 干什么 | 哪节 |
|---|---|---|
| `docker compose exec <服务> sh` | 开个 shell ← **默认用 `sh`，不用 `bash`** | `07` §4.2 |
| `docker compose exec <服务> bash` | 想要补全/历史时才用（**caddy 没有 bash**） | `07` §4.2 |
| `docker compose exec <服务> <命令>` | 跑一条就走，不进交互 | `05` |
| `docker run --rm <镜像> sh -c '<命令>'` | **不启动服务**，拿镜像跑个一次性容器 | `06`、`07` 练习 |

**本项目常用的几条：**

```bash
docker compose exec mysql mysql -uroot -prbac_root_123        # 连数据库
docker compose exec mysql du -sh /var/lib/mysql               # 数据多大
docker compose exec redis redis-cli -a rbac_redis_123 ping    # 探 redis
docker compose exec caddy sh                                  # caddy 只有 sh
```

> 🔑 **`exec` 是用来"看"的，不是用来"改"的。** 容器里改的东西下次重建就没了——回源头改（配置文件 / `.env` / 代码）。（`07` §4.3）

## 4. 起停

| 命令 | 容器 | 网络 | **卷（数据）** | 什么时候用 | 哪节 |
|---|---|---|---|---|---|
| `docker compose up -d` | 建/更新 | 建 | 保留 | **日常起服务**（幂等，随便敲） | `03` |
| `docker compose stop` | 停但**不删** | 保留 | ✅ 保留 | 临时停一下 | `05` §7 |
| `docker compose start` | 原地复活 | — | ✅ 保留 | 接上面 | — |
| `docker compose restart <服务>` | 重启进程 | — | ✅ 保留 | **改完 `Caddyfile` / `nginx.conf`** | `07` §5.3 |
| `docker compose down` | **删** | **删** | ✅ **保留** | 升级、改配置、重来 | `05` §7 |
| `docker compose down -v` | **删** | **删** | 💀 **删** | ⚠️ 只在"我要从零开始" | `05` §7 |

```bash
docker compose up -d <服务>              # 只起某一个
docker compose --profile extra up -d     # 带上扩展层（06；注意 --profile 放 up 前面）
docker compose up -d rabbitmq            # 点名带 profile 的服务，profile 自动激活
```

## 5. 构建与上线

**标准循环**（`07` §5.1、`docs/09-部署上线指南.md` §302）：

```bash
# ① 开发机
git add . && git commit -m "..." && git push origin feat/rbac-mvp

# ② 服务器
ssh root@106.15.89.180
cd /root/project/RBAC-Server && git pull origin feat/rbac-mvp
cd deploy && docker compose up -d --build

# ③ 验证
docker compose ps
docker compose logs --tail=30 backend     # Started RbacServerApplication = 就绪
```

**`--build` 到底要不要加**（`07` §5.3）：

| 改了什么 | 要 `--build` 吗 |
|---|---|
| 前后端**代码**、`Dockerfile` | ✅ **必须**（代码 `COPY` 进镜像，不重建进不去） |
| `.env`、`docker-compose.yml` | ❌ 不用（`up -d` 自己会重建容器） |
| `Caddyfile`、`nginx.conf` | ❌ 不用，但要 `restart <服务>` 让进程**重读** |

> 🔑 **`--build` 管镜像，`up -d` 管容器。改的东西在镜像里才要 `--build`。**
> 🔑 **`up -d` 是增量的**：没变的服务它不碰。改后端代码不会重启 mysql。

```bash
docker compose build <服务>              # 只构建不启动
docker compose build --no-cache <服务>   # 不用缓存重建（怀疑缓存有问题时，02）
```

## 6. 清理磁盘

| 命令 | 删什么 | 安全吗 | 哪节 |
|---|---|---|---|
| `docker system df` | （只看）谁占了磁盘 | ✅ | `07` §6.1 |
| `docker image prune` | 悬空镜像（`<untagged>` 且没容器在用） | ✅ **日常打扫** | `07` §6.5 |
| `docker builder prune` | 构建缓存（删了只是下次构建慢点） | ✅ **日常打扫** | `07` §6.5 |
| `docker image prune -a` | **所有**没容器在用的镜像 | ⚠️ 下次要重新 pull | `07` §6.5 |
| `docker volume ls` | （只看）有哪些卷 | ✅ | `05` §4 |
| `docker volume rm <名字>` | 指定的卷 | ⚠️ 看清楚再删 | `07` §6.5 |
| `docker volume inspect <名字>` | （只看）卷在哪、多久建的 | ✅ | `05` §4 |

```bash
docker system df                    # 先看
docker image prune                  # 再删
docker builder prune
docker system df                    # 对比
```

> 🔑 **日常只用 `image prune` + `builder prune`**——删的都是能重新生成的东西，最坏结果是下次慢一点。
> **服务器每 `--build` 几十次磁盘就会告警，这是运维日常，不是出事才做。**

## 7. 症状 → 怎么查

| 症状 | 先敲这个 | 大概率是 | 哪节 |
|---|---|---|---|
| `port is already allocated` | `docker ps` / `lsof -i :80` | 端口被占（nginx↔caddy 抢 80） | `01`、`06` §2.6 |
| `ps` 里根本看不到那个容器 | **`docker compose ps -a`** | 启动就崩，躺在 `Exited` | `07` §3.2 |
| 容器一直 `Restarting` | `logs --tail=50 <服务>` | 同一个错反复出现——**是一个问题不是十个** | `07` §3.2 |
| mysql 一直 `unhealthy` | `logs mysql` | 探针失败，手动跑一遍 `healthcheck.test` | `04` |
| backend 连不上 mysql | `logs backend` | ① mysql 没 ready ② **密码不一致** | `04`、`docs/ops/01` |
| 改了 `.env` 密码不生效 | — | **出厂设置**：卷不空，mysql 不读环境变量 | `05` §5 |
| 改了 `Caddyfile` 没生效 | `restart caddy` | 文件新了 ≠ 进程重读了 | `07` §5.3 |
| 改了代码没生效 | `up -d --build` | 忘了 `--build`，镜像还是旧的 | `07` §5.3 |
| 网页 502 | `ps` 看 backend | 上游没起，或 upstream 指错 | `06` §4.5 |
| 刷新页面 404 | — | SPA 回退没配（本项目已配 `try_files`） | `06` §4.5 |
| 证书签不下来 | `logs caddy` | DNS 没生效 / 80 没放行 | `06` §4.3、`docs/ops/02` |
| 证书突然签不出 | — | **LE 限流**（一周 5 张），等一周，别删 `caddy-data` | `05`、`06` §4.4 |
| 磁盘满 | `docker system df` + `df -h` | 悬空镜像 / 构建缓存 / 孤儿卷 / 日志 | `07` §6 |
| `bash: not found` | 换 `sh` | Alpine 镜像（caddy）没 bash | `07` §4.2 |
| 容器里改的东西没了 | — | 可写层随重建蒸发，回源头改 | `05`、`07` §4.3 |

> 🔑 **一半以上的坑根子是同一件事：你改的东西住在哪一层。**
> 镜像（代码）→ 要 `--build` · 容器（环境变量）→ `up -d` · 挂载（配置文件）→ 改文件 + `restart` · 卷（数据）→ 只有 `-v` 动得了。

## 9. ⚠️ 红区：敲之前停三秒

| 命令 | 会发生什么 |
|---|---|
| `docker compose down -v` | 💀 **删本项目的卷** = 清库。没有回收站，没有二次确认。（`05` §7） |
| `docker system prune -a --volumes` | 💀💀 **删整台机器上所有没在用的卷**。如果你刚 `down` 过，`rbac-server_mysql-data` 就是"没在用的卷"——**你以为在打扫，其实在清库**。（`07` §6.5） |
| `docker volume rm rbac-server_mysql-data` | 💀 同上，只是更直接 |
| 服务器上 `git reset --hard` | 覆盖服务器本地改动（部署机上通常正是你要的，`docs/09` §301） |

> 🔑 **`-v` 挨着 `down` 很近，手快一点就出去了。**
> **在任何有真实数据的环境上，永远不要打这三个字符。**
