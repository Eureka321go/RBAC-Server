# IM 接口文档（REST + WebSocket）

> 本文档据代码实现整理，覆盖 IM 聊天系统的全部对客户端接口。
> 涉及模块：`backend`（业务/逻辑层，REST + Kafka 消费）与 `im-gateway`（Netty WebSocket 网关）。
> 里程碑 1~10 已实现：单聊/群聊、离线增量同步、富媒体、链接卡片、撤回、@提及、已读回执。

---

## 1. 总体架构

```
                 REST (HTTP)                       WebSocket (Netty)
  客户端  ──────────────────────►  backend :8080/api        客户端 ──────────────► im-gateway :9001 /im
   │        会话列表 / 拉消息 / 群管理 / 上传预签名                  │   长连接：收发实时帧
   │                                                              │
   └──────────────────────────────────────────────────────────────┘
                         上行 SEND/RECALL/READ  ─(Kafka im-inbound)─►  backend logic
                         下行 PUSH/ACK/ERROR/READ ◄─(Kafka im-outbound)─  backend logic
```

- **REST 接口**：走 backend，端口 `:8080`，统一 context-path `/api`，即全部路径前缀 `/api/im`。
- **WebSocket**：走独立的 `im-gateway`（Netty），默认端口 `:9001`，路径 `/im`。**不经过 `/api`**。
- **消息流**：客户端上行帧 → 网关 → Kafka `im-inbound` → backend 逻辑层（校验/定序/落库）→ Kafka `im-outbound` → 目标网关 → 推给在线设备。离线设备靠 REST 增量拉取补齐。

---

## 2. 通用约定

### 2.1 REST 响应包裹

所有 REST 接口返回统一 `Result<T>`：

```json
{ "code": 200, "message": "success", "data": { } }
```

### 2.2 鉴权

- **REST**：沿用 RBAC 登录态（`Authorization: Bearer <JWT>`）。用户 id 从登录态取（`SecurityUtils.getUserId()`），请求体/参数中的发送者身份不可信。
- **WebSocket**：握手时通过 query 参数 `token` 传 JWT，网关校验失败直接 `401` 关闭连接。连接建立后，服务端以连接身份为准，忽略帧内伪造的 `senderId`/`deviceId`。

### 2.3 会话 ID（cid）格式

| 会话类型 | cid 形态 | 说明 |
|---------|---------|------|
| 单聊 SINGLE | `c_<minUserId>_<maxUserId>` | 两个用户 id 升序拼接，天然去重 |
| 群聊 GROUP | `g_<groupId>` | 群 id |

## 3. REST 接口

### 3.1 会话列表同步

`GET /api/im/conversations`

拉取当前用户的全部会话及位点，用于会话列表渲染与未读/提及红点。

响应 `data`：`ImConversationVO[]`

| 字段 | 类型 | 说明 |
|------|------|------|
| cid | string | 会话 id |
| type | string | `SINGLE` / `GROUP` |
| groupId | number\|null | 群 id（单聊为 null） |
| lastMsgSeq | number | 会话最新消息 seq |
| lastMsgPreview | string | 最后一条消息摘要文案 |
| lastReadSeq | number | 我的已读位点 |
| unreadCount | number | 未读数 |
| mentionSeq | number | 我被 @ 命中的最新消息 seq |
| hasMention | boolean | `mentionSeq > lastReadSeq` → "有人@我"强提醒 |
| peerReadSeq | number\|null | 单聊对端已读位点；群聊为 null |

### 3.2 单会话增量拉取

`GET /api/im/messages`

按 seq 增量拉取某会话的历史/离线消息。

查询参数：

| 参数 | 必填 | 说明 |
|------|------|------|
| cid | 是 | 会话 id |
| sinceSeq | 否 | 从该 seq 之后拉取（不含）；不传从头 |
| limit | 否 | 单页条数，服务端有默认与上限 |

响应 `data`：`PullResult`

| 字段 | 类型 | 说明 |
|------|------|------|
| messages | ImMessageVO[] | 消息列表（见下） |
| hasMore | boolean | 是否还有更多 |
| nextSinceSeq | number | 下一页 sinceSeq 游标 |

`ImMessageVO`：

| 字段 | 类型 | 说明 |
|------|------|------|
| cid | string | 会话 id |
| seq | number | 会话内单调序号 |
| msgId | string | 服务端消息 id |
| senderId | number | 发送者 |
| type | string | `TEXT`/`IMAGE`/`AUDIO`/`FILE`/`SYSTEM`/`RECALL` |
| body | object | 消息体（按 type，见 §4.5） |
| recalled | boolean | 是否已撤回（撤回后 body 正文被清空） |
| ts | number | 服务端时间戳（ms） |

> 富媒体消息（IMAGE/AUDIO/FILE）拉取时，body 会附加临时预签名 GET `url`，与在线推送形态一致。

### 3.3 群管理

统一前缀 `/api/im/groups`，请求/响应包裹同 §2.1。

| 方法 & 路径 | 请求体 | 说明 |
|------------|--------|------|
| `POST /` | `{ "name": string, "memberIds": number[] }` | 建群，返回 `{ groupId, cid }` |
| `POST /{groupId}/members` | `{ "userIds": number[] }` | 添加成员 |
| `DELETE /{groupId}/members/me` | — | 主动退群 |
| `DELETE /{groupId}/members/{userId}` | — | 踢人（需管理权限） |
| `PATCH /{groupId}` | `{ "name": string }` | 改群名 |
| `POST /{groupId}/owner` | `{ "newOwnerId": number }` | 转让群主 |
| `PUT /{groupId}/members/{userId}/role` | `{ "role": string }` | 设成员角色（`OWNER`/`ADMIN`/`MEMBER`） |
| `PUT /{groupId}/members/{userId}/mute` | `{ "muted": boolean }` | 禁言/解禁 |
| `GET /{groupId}` | — | 群详情 `ImGroupVO` |
| `GET /{groupId}/members` | — | 群成员 `ImGroupMemberVO[]` |
| `DELETE /{groupId}` | — | 解散群（群主） |

`ImGroupVO`：`{ groupId, name, ownerId, memberCount, myRole }`
`ImGroupMemberVO`：`{ userId, role, muted }`

### 3.4 富媒体上传预签名

`POST /api/im/upload/presign`

发送图片/音频/文件前先调此接口拿直传地址，客户端用返回的 `uploadUrl` 直接 PUT 到对象存储，再用 `objectKey` 发 WebSocket 消息。

请求体 `PresignRequest`：

| 字段 | 类型 | 说明 |
|------|------|------|
| cid | string | 目标会话 |
| type | string | `IMAGE` / `AUDIO` / `FILE` |
| filename | string | 原文件名（仅用于取扩展名，不可信、会被清洗） |
| mime | string | MIME 类型 |
| size | number | 字节大小 |

响应 `PresignResult`：

| 字段 | 类型 | 说明 |
|------|------|------|
| objectKey | string | 对象键，发送消息时放进 body |
| uploadUrl | string | 预签名 PUT URL（限时） |
| expiresIn | number | 有效秒数 |

> 服务端在“发送”时会二次校验：objectKey 必须为本服务给该会话签发的形态、对象真实存在、大小/MIME 复核，校验不过回 `ERROR`（见 §4.6）。

## 4. WebSocket 协议

### 4.1 连接与握手

```
ws://<gateway-host>:9001/im?token=<JWT>&deviceId=<设备标识>
```

- `token`：必填，登录 JWT。网关在 WS 升级前校验，失败返回 `401` 并关闭。
- `deviceId`：可选，缺省 `default`。用于多端在线（同一用户多设备各自登记路由，消息扇出到每个在线设备）。
- 握手成功后，网关将连接登记到本机连接表与 Redis 全局路由（`route:user:<uid>`）。

### 4.2 心跳与超时

- 网关启用空闲检测，默认 `60s` 读空闲即关闭连接（`heartbeat-idle-seconds`）。
- 客户端应在空闲窗口内发送任意帧（可用 WebSocket ping / 空 SEND 之外的保活帧）维持连接。
- 连接断开（主动/超时/异常）时，网关自动清理本机连接表与 Redis 路由。

### 4.3 消息信封 Envelope

上行、下行、推送统一使用一个 JSON 信封（`TextWebSocketFrame`）：

```json
{
  "op": "SEND",
  "cid": "c_1_2",
  "senderId": 1,
  "deviceId": "web-1",
  "clientMsgId": "uuid-本地生成",
  "type": "TEXT",
  "body": { "text": "hello" },
  "seq": 100,
  "msgId": "服务端消息id",
  "ts": 1737000000000
}
```

| 字段 | 上行填 | 下行有 | 说明 |
|------|:-----:|:-----:|------|
| op | ✔ | ✔ | 操作类型，见 §4.4 |
| cid | ✔ | ✔ | 会话 id |
| senderId | （忽略） | ✔ | 上行由服务端以连接身份覆盖 |
| deviceId | （忽略） | — | 同上 |
| clientMsgId | ✔ | ✔ | 客户端本地生成，用于幂等 + ACK 回执关联 |
| type | ✔ | ✔ | 消息类型 |
| body | ✔ | ✔ | 消息体 |
| seq | — | ✔ | 服务端定序后回填 |
| msgId | — | ✔ | 服务端消息 id |
| ts | — | ✔ | 服务端时间戳 |

### 4.4 op 一览

**上行（客户端 → 服务端）**

| op | 说明 |
|----|------|
| `SEND` | 发送消息（文本/富媒体） |
| `RECALL` | 撤回消息，`body.targetSeq` 指定被撤回消息 seq |
| `READ` | 已读上报，`body.readSeq` 指定读到的位点 |

**下行（服务端 → 客户端）**

| op | 说明 |
|----|------|
| `ACK` | 网关对 `SEND` 的即时接收回执，携带原 `clientMsgId`（此时还没有 seq） |
| `PUSH` | 实时新消息推送（含普通消息、撤回控制消息 `type=RECALL`、系统消息 `type=SYSTEM`） |
| `READ` | 单聊已读回执（对端读到你消息时收到），`body.readSeq` 为对端已读位点 |
| `ERROR` | 发送/撤回被拒，`body.reason` 为错误码（见 §4.6） |

### 4.5 各类型 body 形态

**TEXT（文本，可带 @提及，仅群聊生效）**
```json
{ "text": "hi @all", "mentions": [10, 11], "mentionAll": true }
```
- `mentions`：被 @ 的用户 id 数组（可选）
- `mentionAll`：是否 @全体（可选，默认仅群管理员可用）
- 校验：@ 非群成员 → `MENTION_NOT_MEMBER`；无权限 @全体 → `MENTION_ALL_FORBIDDEN`（整条消息被拒）

**IMAGE / AUDIO / FILE（富媒体）**
```json
{ "objectKey": "预签名返回的 key", "mime": "image/png", "size": 12345, "filename": "a.png" }
```
- 上行必带 `objectKey`（来自 §3.4 预签名）
- 下行/拉取时 body 会被附加临时预签名 GET `url` 供直接展示/下载

**RECALL（撤回控制消息，仅下行 PUSH）**
```json
{ "targetSeq": 100 }
```
- 收到后客户端将本地 seq=targetSeq 的消息渲染为“已撤回”

**SYSTEM（系统消息，仅下行）**：入群/退群/改名等系统提示，body 由服务端约定。

### 4.6 错误码（ERROR.body.reason）

| reason | 触发场景 |
|--------|---------|
| `NOT_MEMBER` | 发送/撤回时非会话成员 |
| `MUTED` | 群内被禁言 |
| `STORAGE_UNAVAILABLE` | 富媒体校验时对象存储不可用 |
| `INVALID_OBJECT` | objectKey 非本会话合法签发形态 |
| `OBJECT_NOT_FOUND` | 对象不存在（未完成直传） |
| `TYPE_UNSUPPORTED` | 不支持的媒体类型 |
| `TOO_LARGE` | 超过大小上限 |
| `MIME_NOT_ALLOWED` | MIME 不在白名单 |
| `MENTION_NOT_MEMBER` | @ 了非群成员 |
| `MENTION_ALL_FORBIDDEN` | 无权限 @全体 |
| `RECALL_TARGET_NOT_FOUND` | 撤回目标不存在 / targetSeq 缺失非法 |
| `NOT_RECALLABLE` | 目标为 SYSTEM/RECALL 类型，不可撤回 |
| `RECALL_NO_PERMISSION` | 非本人且非群管理员 |
| `RECALL_WINDOW_EXPIRED` | 超过撤回时间窗（默认 120s） |

## 5. 典型时序

### 5.1 发送文本消息

```
客户端 ──SEND {clientMsgId, cid, type:TEXT, body:{text}}──► 网关
网关   ──ACK {clientMsgId}──► 客户端                （即时确认已接收）
网关   ──(Kafka im-inbound)──► backend
backend: 幂等去重 → 成员/禁言校验 → 定序落库 → 扇出
backend ──(Kafka im-outbound, PUSH {seq,msgId,ts})──► 各在线成员网关 ──► 各设备
```
- 客户端收到 `ACK` 表示服务器已受理；收到 `PUSH`（匹配 `clientMsgId`）拿到最终 `seq` 完成本地消息状态更新。
- 校验不过则收到 `ERROR`（携带 `clientMsgId`/`reason`），不会有 PUSH。

### 5.2 已读回执（单聊）

```
读者 ──READ {cid, body:{readSeq}}──► 网关 ──► backend
backend: 成员校验 → 钳制到 lastMsgSeq → 前向单调推进 last_read_seq
backend ──PUSH READ {cid, body:{readSeq}}──► 对端（发消息的人）
```
- 群聊只推进位点、不扇出回执。
- 会话列表侧对端已读位点通过 `ImConversationVO.peerReadSeq` 暴露。

### 5.3 撤回

```
操作者 ──RECALL {cid, body:{targetSeq}}──► 网关 ──► backend
backend: 6 步校验（成员/目标存在/类型可撤/幂等/权限/时间窗）
        → 清正文并标记 recalled → 追加 type:RECALL 控制消息
backend ──PUSH {type:RECALL, body:{targetSeq}}──► 全体成员
```

## 6. 部署参数速查

| 项 | 默认值 | 来源 |
|----|-------|------|
| backend HTTP 端口 | `8080`，context-path `/api` | backend `application.yml` |
| 网关 WS 端口 | `9001`，路径 `/im` | `im.gateway.ws-port` |
| 网关 actuator 端口 | `8090` | im-gateway `server.port` |
| 心跳空闲超时 | `60s` | `im.gateway.heartbeat-idle-seconds` |
| 撤回时间窗 | `120s` | `rbac.im.recall-window-seconds` |
| @全体仅管理员 | `true` | `rbac.im.mention-all-admin-only` |
| Kafka 上行 topic | `im-inbound` | `ImKafkaTopics.IN` |
| Kafka 下行 topic | `im-outbound` | `ImKafkaTopics.OUT` |
| Redis 路由键 | `route:user:<uid>` (hash: deviceId→gatewayId) | `RouteService` |

> 网关的 `rbac.jwt.secret` 必须与 backend 一致，否则 WS 握手校验不过。
